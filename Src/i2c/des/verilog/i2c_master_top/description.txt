i2c_master_top is the Wishbone top-level interface module of the OpenCores I2C master core. Its main function is to provide a register read/write interface to the host, allowing software to configure the I2C clock prescaler, enable the core, write transmit data, issue commands such as START, STOP, READ, WRITE, and ACK, read received data, check status, and handle interrupts. The module itself does not directly implement the complete I2C bit-level timing sequence. Instead, it passes the configuration, commands, and transmit data stored in its registers to the internally instantiated i2c_master_byte_ctrl, which then performs I2C byte transfers, START/STOP generation, ACK/NACK handling, bus-busy detection, arbitration-lost detection, and SCL/SDA pad control. The source code defines this module as the top-level module of a Wishbone I2C Master controller, and the specification also describes the core as an I2C master core with a Wishbone Classic interface.

The module has two reset inputs: wb_rst_i and arst_i. wb_rst_i is a synchronous active-high Wishbone reset, which takes effect on the rising edge of wb_clk_i. arst_i is an asynchronous reset, and its active level is determined by the parameter ARST_LVL. In the code, the asynchronous reset is normalized into an internal active-low reset signal by rst_i = arst_i ^ ARST_LVL. During reset, prer is initialized to 16'hffff, while ctr, txr, cr, al, rxack, tip, irq_flag, and wb_inta_o are cleared to zero. This behavior is consistent with the specification, where the prescale register reset value is 0xffff and the control, command, and status-related registers reset to 0x00.

The Wishbone interface consists of wb_clk_i, wb_rst_i, wb_adr_i, wb_dat_i, wb_dat_o, wb_we_i, wb_stb_i, wb_cyc_i, wb_ack_o, and wb_inta_o. wb_clk_i is the main clock of the module, and all synchronous logic is updated on its rising edge. wb_adr_i[2:0] selects the internal register to be accessed. wb_dat_i is the write data from the host, and wb_dat_o is the read data returned by the module. wb_we_i indicates that the current access is a write access. wb_stb_i and wb_cyc_i together indicate a valid Wishbone bus cycle. The module generates a registered acknowledge response using wb_ack_o <= wb_cyc_i & wb_stb_i & ~wb_ack_o, so wb_ack_o indicates that the current access has been accepted by the module. Internal writes are not controlled by wb_we_i alone, but by wb_wacc = wb_we_i & wb_ack_o. In other words, internal registers are updated only during an acknowledged Wishbone write cycle.

wb_dat_o is a registered read-data output. In the RTL, it is updated on every rising edge of wb_clk_i according to wb_adr_i, rather than only during a valid read cycle. Address 3'b000 reads prer[7:0], address 3'b001 reads prer[15:8], address 3'b010 reads ctr, address 3'b011 reads rxr, address 3'b100 reads sr, address 3'b101 reads txr, address 3'b110 reads cr, and address 3'b111 reads 8'h00. The standard register mapping is consistent with the specification: 0x00 is the prescale low byte, 0x01 is the prescale high byte, 0x02 is the control register, 0x03 reads as the receive register and writes as the transmit register, and 0x04 reads as the status register and writes as the command register. Note that this RTL implementation additionally allows txr to be read at 0x05 and the internal cr to be read at 0x06, but these two addresses are not part of the standard software-visible register interface listed in the specification.

Regular register writes occur when wb_wacc is high. Address 3'b000 writes prer[7:0], address 3'b001 writes prer[15:8], address 3'b010 writes ctr, and address 3'b011 writes txr. Other addresses do not modify these regular registers. prer is a 16-bit clock prescale register. It sets the I2C SCL clock rate and is passed to i2c_master_byte_ctrl through the clk_cnt input. According to the specification, the prescale register should be configured while the core enable bit is cleared, and its reset value is 0xffff. ctr is the control register. ctr[7] is EN, which enables the I2C core; ctr[6] is IEN, which enables the interrupt output; and ctr[5:0] are reserved bits. txr is the transmit register, which holds the next byte to be transmitted over I2C. When a slave address is transmitted, txr[0] represents the I2C read/write bit: 1 means reading from the slave, and 0 means writing to the slave.

cr is the command register, but it has special write and auto-clear behavior that differs from regular registers. The host writes cr through address 3'b100, but the command register accepts the write only when core_en is high, that is, when ctr[7] is set. If the core is not enabled, the command is ignored even if a Wishbone write access occurs. cr[7] is STA, which requests a START or repeated START condition. cr[6] is STO, which requests a STOP condition. cr[5] is RD, which requests reading one byte from the slave. cr[4] is WR, which requests writing one byte to the slave. cr[3] is ACK, which controls whether the master returns ACK or NACK in receive mode: 0 means sending ACK, and 1 means sending NACK. cr[2:1] are reserved bits. cr[0] is IACK, which clears the pending interrupt flag. The specification also states that the STA, STO, RD, WR, and IACK bits in the command register are automatically cleared, and that a standard read from address 0x04 returns the status register rather than the command register.

The command bits in the command register are decoded into internal control signals: sta = cr[7], sto = cr[6], rd = cr[5], wr = cr[4], ack = cr[3], and iack = cr[0]. These signals are connected to the start, stop, read, write, and ack_in ports of i2c_master_byte_ctrl, while txr is connected to its din port. After the byte controller completes a command, it notifies the top-level module through done, which corresponds to cmd_ack. If done or i2c_al is asserted, the top-level module clears cr[7:4], namely the START, STOP, READ, and WRITE command bits. At the same time, the reserved bits cr[2:1] and the interrupt acknowledge bit cr[0] are also automatically cleared. When arbitration is lost, the current command bits are also cleared, cancelling the ongoing command.

rxr is the received-data output from i2c_master_byte_ctrl. It represents the most recent byte received from the I2C bus and is read through address 0x03. sr is the assembled status register and is read through the standard address 0x04. Its bit mapping is: sr[7] = rxack, indicating the acknowledge status of the most recent transfer; sr[6] = i2c_busy, indicating whether the I2C bus is busy; sr[5] = al, indicating arbitration-lost status; sr[4:2] = 3'h0, reserved bits that always read as zero; sr[1] = tip, indicating that a transfer is in progress; and sr[0] = irq_flag, indicating that an interrupt is pending. The status register definition is consistent with the specification. In the specification, RxACK = 1 means no acknowledge was received, while RxACK = 0 means an acknowledge was received. Busy is set after a START condition is detected and cleared after a STOP condition is detected. TIP is high while a transfer is in progress. IF is set when a byte transfer completes or arbitration is lost.

The status bits rxack, tip, irq_flag, and al are latched and maintained by the top-level module. rxack samples the byte controller output irxack on each clock cycle and reflects whether the slave acknowledged the previous transfer. tip is updated by tip <= rd | wr, so it indicates whether a read or write byte command is currently active. After the command completes or arbitration is lost, rd and wr are cleared and tip is cleared accordingly. irq_flag is updated by (done | i2c_al | irq_flag) & ~iack, so a byte command completion or arbitration loss sets the interrupt flag, while a host write with IACK clears it. al is updated by al <= i2c_al | (al & ~sta), so once arbitration loss is detected, it remains latched until a new START command is issued.

wb_inta_o is the Wishbone-side interrupt output. It is not directly equal to done or i2c_al; instead, it is generated from irq_flag && ien, where ien = ctr[6]. This means that even when interrupt output is disabled, irq_flag is still set when a byte transfer completes or arbitration is lost. IEN only determines whether the pending interrupt is actually driven onto wb_inta_o. The host must write the IACK bit in the command register to clear irq_flag and remove the pending interrupt condition.

The I2C pad interface consists of scl_pad_i, scl_pad_o, scl_padoen_o, sda_pad_i, sda_pad_o, and sda_padoen_o. scl_pad_i and sda_pad_i are the sampled inputs from the external I2C SCL and SDA lines, used to observe bus levels, detect START/STOP conditions, handle clock stretching, and detect arbitration loss. scl_pad_o and sda_pad_o are the line output values generated by the byte controller, while scl_padoen_o and sda_padoen_o are the corresponding output-enable controls and are active low. Since the I2C bus requires open-drain or open-collector behavior, these pad signals are normally connected to tri-state buffers at a higher hierarchy level, with external pull-up resistors pulling SCL and SDA high. The specification also explicitly states that SCL and SDA require open-drain/open-collector outputs, external pull-ups, and tri-state buffers added at a higher hierarchy level.

In summary, i2c_master_top is the Wishbone register and control wrapper for the I2C master core. It handles host-side register reads and writes, generates Wishbone acknowledge responses, stores prescale, control, transmit, and command information, maintains receive, status, and interrupt state, and converts software-written I2C commands into control inputs for i2c_master_byte_ctrl. The actual I2C byte transfer and SCL/SDA timing control are performed by the byte controller, while the top-level module exposes the results through Wishbone-readable status registers and the interrupt output.

module i2c_master_top(
	wb_clk_i, wb_rst_i, arst_i, wb_adr_i, wb_dat_i, wb_dat_o,
	wb_we_i, wb_stb_i, wb_cyc_i, wb_ack_o, wb_inta_o,
	scl_pad_i, scl_pad_o, scl_padoen_o, sda_pad_i, sda_pad_o, sda_padoen_o );

Input ports:
    wb_clk_i: Wishbone clock input and main synchronous clock for this module. It defines the update timing for Wishbone acknowledge generation, read-data registration, register writes, status latching, and interrupt-output registration.
    wb_rst_i: Synchronous active-high Wishbone reset input. When asserted on the rising edge of wb_clk_i, it resets the module’s internal registers and status state, including prer, ctr, txr, cr, al, rxack, tip, irq_flag, and wb_inta_o. It is also passed to the byte controller as its synchronous reset.
    arst_i: Asynchronous reset input. Its active level is selected by the parameter ARST_LVL. The module normalizes it internally as rst_i = arst_i ^ ARST_LVL, producing an active-low asynchronous reset used by the resettable sequential logic and passed to the byte controller as nReset.
    wb_adr_i[2:0]: Wishbone register address input. It selects the register to read or write. Standard addresses are 0x00 for PRER[7:0], 0x01 for PRER[15:8], 0x02 for CTR, 0x03 for reading RXR or writing TXR, and 0x04 for reading SR or writing CR. The RTL also allows readback of TXR at 0x05, readback of CR at 0x06, and returns zero at 0x07.
    wb_dat_i[7:0]: 8-bit Wishbone write-data input. During a qualified write access, this value is written to the selected writable register, such as the prescale register bytes, control register, transmit register, or command register. Command-register writes are accepted only when the core enable bit CTR[7] is set.
    wb_we_i: Wishbone write-enable input. When high during an acknowledged Wishbone access, the access is treated as a write. Actual register writes are qualified by wb_wacc = wb_we_i & wb_ack_o.
    wb_stb_i: Wishbone strobe input. It indicates that the current bus access targets this core. Together with wb_cyc_i, it is used to generate the registered acknowledge response wb_ack_o.
    wb_cyc_i: Wishbone cycle input. It indicates that a valid Wishbone bus cycle is active. When both wb_cyc_i and wb_stb_i are asserted, the module generates an acknowledge pulse through wb_ack_o.
    scl_pad_i: Sampled input from the external I2C serial clock line, SCL. It is passed to the byte controller so the core can observe the actual SCL bus level, support clock stretching, detect bus activity, and handle multi-master arbitration behavior.
    sda_pad_i: Sampled input from the external I2C serial data line, SDA. It is passed to the byte controller so the core can sample received data bits, observe acknowledge bits, detect START and STOP conditions, determine bus busy state, and detect arbitration loss.

Output port:
    wb_dat_o[7:0]: Registered 8-bit Wishbone read-data output. It returns the register value selected by wb_adr_i, including PRER, CTR, RXR, SR, optional TXR/CR readback values, or zero for the reserved address. In the RTL, it is updated on every rising edge of wb_clk_i according to the current address.
    wb_ack_o: Registered Wishbone acknowledge output. It indicates that the module has accepted the current Wishbone access. It is generated as wb_ack_o <= wb_cyc_i & wb_stb_i & ~wb_ack_o, producing an acknowledge pulse for valid bus accesses. It is also used internally with wb_we_i to qualify register writes.
    wb_inta_o: Registered Wishbone interrupt-request output. It is asserted when the internal interrupt flag irq_flag is set and interrupt enable CTR[6] is high. The interrupt flag is set when a byte command completes or arbitration is lost, and is cleared when the host writes the IACK bit in the command register.
    scl_pad_o: I2C SCL line output value generated by the byte controller. It is intended to connect to an external or upper-level open-drain or tri-state buffer for the I2C serial clock line. The core uses this signal together with scl_padoen_o to pull SCL low or release it.
    scl_padoen_o: Active-low output-enable control for the I2C SCL line. When low, the SCL output driver is enabled and the core can pull SCL low. When high, SCL should be released to high impedance so an external pull-up resistor can pull the line high.
    sda_pad_o: I2C SDA line output value generated by the byte controller. It is intended to connect to an external or upper-level open-drain or tri-state buffer for the I2C serial data line. The core uses this signal together with sda_padoen_o to pull SDA low or release it.
    sda_padoen_o: Active-low output-enable control for the I2C SDA line. When low, the SDA output driver is enabled and the core can pull SDA low. When high, SDA should be released to high impedance so an external pull-up resistor can pull the line high.


Processing Flow

The processing flow of i2c_master_top starts with a Wishbone bus access from the host. When wb_cyc_i and wb_stb_i are asserted, the module generates a registered acknowledge response through wb_ack_o. For write accesses, an internal write is performed only when wb_we_i and wb_ack_o are both high, forming the qualified write-access signal wb_wacc. For read accesses, the registered output wb_dat_o is updated according to wb_adr_i, returning the selected prescale, control, receive, status, transmit, command, or reserved value.

During configuration, the host first programs the prescale register prer through addresses 0x00 and 0x01 to set the I2C SCL timing. The host then writes the control register ctr at address 0x02 to enable the core through ctr[7], and optionally enables interrupt output through ctr[6]. The transmit register txr can then be loaded through address 0x03 with either a slave address byte or a data byte to be transmitted on the I2C bus.

After the core is enabled, the host issues I2C commands by writing the command register cr at address 0x04. The command write is accepted only when core_en is high. The command bits are decoded into sta, sto, rd, wr, ack, and iack, which represent START, STOP, READ, WRITE, ACK/NACK control, and interrupt acknowledge. These decoded command signals, together with the prescale value and transmit data, are passed to the instantiated i2c_master_byte_ctrl.

The byte controller performs the requested I2C operation on the SCL and SDA lines. It uses scl_pad_i and sda_pad_i to observe the external bus and drives scl_pad_o, scl_padoen_o, sda_pad_o, and sda_padoen_o to control the open-drain style I2C interface. During this operation, the top-level module monitors byte-controller outputs such as done, irxack, rxr, i2c_busy, and i2c_al.

When the byte controller completes the requested byte-level command, it asserts done. The top-level module then clears the active command bits in cr[7:4], updates tip, latches the received acknowledge status into rxack, and sets irq_flag. If arbitration is lost, i2c_al sets the latched arbitration-lost bit al, clears the active command bits, and also sets irq_flag. The received byte from the byte controller is available through rxr and can be read by the host from address 0x03.

The host monitors operation progress and completion by reading the status register sr at address 0x04. The status register reports received acknowledge status, bus busy state, arbitration lost, transfer in progress, and interrupt pending state. If interrupt output is enabled through ctr[6], a set irq_flag causes wb_inta_o to assert. The host clears the pending interrupt by writing the IACK bit in the command register, which clears irq_flag and deasserts the interrupt output when no other interrupt condition is pending.
