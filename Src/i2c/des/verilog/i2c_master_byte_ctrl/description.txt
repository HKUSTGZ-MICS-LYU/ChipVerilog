i2c_master_byte_ctrl is the byte-level command controller in the OpenCores I2C master. It receives byte-level requests from the upper control logic, including start, stop, read, write, ack_in, and din, translates them into bit-level commands such as START, STOP, READ, WRITE, and NOP for the bit controller, and uses the instantiated i2c_master_bit_ctrl to perform the actual SCL/SDA timing control. This module is responsible for sequencing byte transfers, shifting 8-bit transmit and receive data, handling the ACK/NACK phase, controlling optional STOP generation, and returning a cmd_ack completion pulse to the upper layer when the full byte command sequence is complete. Its role matches the Byte Command Controller described in the specification: it decomposes each byte operation into multiple bit operations for the Bit Command Controller, while using the DataIO Shift Register to hold the current transfer data.

The clock input is clk, and all sequential logic updates on the rising edge of clk. rst is a synchronous active-high reset that restores the shift register, bit counter, FSM state, command outputs, cmd_ack, and ack_out to their idle values on a clock edge. nReset is an asynchronous active-low reset that immediately resets these states when driven low, independent of the clock edge. ena is the I2C core enable input and is passed to the lower-level i2c_master_bit_ctrl; this byte controller itself does not directly use ena to gate the go start condition. clk_cnt[15:0] is the SCL timing or prescale count input passed to the bit controller. In the source code it is commented as 4x SCL, and it is used by the lower-level bit controller to generate bit-level I2C timing rather than acting as a separate clock signal.

Among the control inputs, start requests generation of a START or repeated START condition before the byte operation. In the idle state, if the start condition is valid and start is asserted, the FSM first issues I2C_CMD_START; after the START completes, it continues to the read flow if read is asserted, otherwise it continues to the write flow. stop requests generation of a STOP condition. It can be used together with a read or write operation, in which case the STOP is generated after the byte transfer and ACK/NACK phase, or it can be used alone as a direct STOP command from the idle state. read requests that one byte be read from the I2C bus. The module issues eight bit-level READ commands and shifts the bits sampled on core_rxd into the internal shift register. write requests that one byte be written to the I2C bus. The module loads din into the shift register and transmits eight bits through core_txd in MSB-first order. ack_in is not a handshake signal; it is the ACK/NACK bit driven by the master after receiving a byte. According to I2C semantics, 0 sends ACK and 1 sends NACK, consistent with the ACK bit definition in the command register described by the specification. din[7:0] is the input byte loaded into the shift register for transmission or command sequencing.

For the outputs, cmd_ack is the byte-command completion pulse that notifies the upper layer that the current byte-level command sequence has finished. If the current operation does not request STOP, cmd_ack is generated after the ST_ACK phase completes. If STOP is requested, cmd_ack is delayed until the STOP command completes in ST_STOP. ack_out is the ACK/NACK bit captured from core_rxd during the ACK phase. It is mainly meaningful after write or address transfers, where the ninth bit is driven by the slave. According to the I2C protocol and the RxACK definition in the specification, 0 means ACK received and 1 means no ACK received. dout[7:0] is directly connected to the internal 8-bit shift register sr, so after a read operation completes it contains the received byte. i2c_busy and i2c_al come from the bit controller. i2c_busy indicates that the I2C bus is busy; the specification defines it as being set after START detection and cleared after STOP detection. i2c_al indicates arbitration lost. The byte controller treats i2c_al like an abort/reset condition, returning the FSM to idle and canceling the current byte sequence.

The I2C physical-interface ports are scl_i, sda_i, scl_o, sda_o, scl_oen, and sda_oen. scl_i and sda_i are the SCL and SDA pad input signals from the external I2C bus and are passed to the bit controller. scl_o and sda_o are the output drive values generated by the bit controller. scl_oen and sda_oen are output-enable or release-control signals for open-drain style I2C pads. According to the external connection convention in the OpenCores specification, the I2C lines are held high through external pull-up resistors, and the output-enable controls are used to drive the line when it must be pulled low and release it to high impedance otherwise.

Internally, the module instantiates i2c_master_bit_ctrl with the instance name bit_controller. The byte controller sends bit-level commands to it through core_cmd, provides the transmit bit through core_txd, receives bit-command completion through core_ack, and receives the sampled bit through core_rxd. The i2c_busy, i2c_al, and SCL/SDA input, output, and output-enable signals are generated or handled by the bit controller. In other words, this module does not directly implement the concrete START or STOP waveforms and does not directly handle low-level SCL/SDA timing. Those operations are implemented in i2c_master_bit_ctrl; this module only schedules the bit-level actions in the correct byte-level protocol order.

The core datapath inside the module is the 8-bit shift register sr. When ld is asserted, sr loads a new byte from din. When shift is asserted, sr shifts left by one bit and inserts core_rxd into the least significant bit. During write operations, core_txd defaults to sr[7], so data is transmitted in MSB-first order. During read operations, each time the bit controller completes a READ command, the sampled core_rxd bit is shifted into sr, eventually forming the full received byte. dout is always directly connected to sr, so the received byte is available on dout after the read completes.

The module also contains a 3-bit bit counter, dcnt, which tracks how many bits remain in the current byte transfer. When ld is asserted, dcnt is loaded with 7. Each time shift is asserted, dcnt is decremented. When dcnt reaches zero, the combinational signal cnt_done is asserted, indicating that the current data bit is the last bit of the byte sequence. This counter works together with the shift register to determine when the read or write state should transition into the ACK/NACK phase.

The command launch condition is generated as go = (read | write | stop) & ~cmd_ack. Therefore, the FSM starts from the idle state only when at least one of read, write, or stop is active and the module is not currently asserting cmd_ack. A standalone start assertion without read, write, or stop does not start a command. The role of start is to insert a START or repeated START condition before a read or write command, not to act as an independent command launch request.

The FSM states are ST_IDLE, ST_START, ST_READ, ST_WRITE, ST_ACK, and ST_STOP. In ST_IDLE, if go is asserted, the state-selection priority is start, then read, then write, then stop. If start is asserted, the FSM enters ST_START and issues a START command to the bit controller. If there is no start but read is asserted, it directly enters the read flow. If write is asserted, it enters the write flow. Otherwise, it executes STOP. When leaving idle to start a command, ld is asserted to load din and initialize the bit counter.

In ST_START, the FSM waits for core_ack from the bit controller, indicating that the START condition has completed. After START completes, if read remains asserted, the FSM issues a bit-level READ command and enters ST_READ; otherwise, it issues a bit-level WRITE command and enters ST_WRITE. This state supports both normal START and repeated START; the actual waveform is still generated by the bit controller according to the bus state and command.

In ST_WRITE, the module transmits one byte by repeatedly issuing I2C_CMD_WRITE. Each time core_ack indicates that the current bit write has completed, the FSM checks cnt_done. If cnt_done is not yet asserted, shift is asserted, the shift register advances to the next bit, and the FSM stays in ST_WRITE to issue the next WRITE. If cnt_done is asserted, all eight data bits have been transmitted, so the FSM moves to ST_ACK and issues a READ command to sample the ninth ACK/NACK bit. At this point the ACK/NACK bit is driven by the slave and is later stored in ack_out.

In ST_READ, the module receives one byte by repeatedly issuing I2C_CMD_READ. Each time the bit controller completes a READ and returns core_ack, shift is asserted and the sampled core_rxd bit is shifted into sr. If all eight bits have not yet been received, the FSM remains in ST_READ and issues the next READ. If cnt_done is asserted, the last data bit has been received, so the FSM moves to ST_ACK and issues a WRITE command to transmit the master ACK/NACK bit during the ninth clock cycle. At this point core_txd is driven by ack_in.

ST_ACK handles the ninth ACK/NACK bit. For a write transfer, the previous state scheduled a bit-level READ, so when core_ack arrives, core_rxd is captured into ack_out to indicate whether the slave acknowledged. For a read transfer, the previous state scheduled a bit-level WRITE, so ack_in is driven through core_txd to indicate whether the master acknowledges the received byte or terminates the read with NACK. After the ACK phase completes, if stop is asserted, the FSM enters ST_STOP and issues a STOP command. If stop is not asserted, the FSM returns to ST_IDLE, sets core_cmd to NOP, and generates a one-cycle cmd_ack.

In ST_STOP, the module waits for the bit controller to complete the STOP condition. When core_ack becomes active, the FSM returns to ST_IDLE, sets core_cmd to NOP, and generates the cmd_ack completion pulse. Because STOP has its own state, when a read or write command also requests STOP, the upper layer receives cmd_ack only after the STOP condition has actually completed, rather than immediately after the ACK/NACK phase.

For reset and exception handling, driving nReset low asynchronously clears sr, dcnt, and the FSM-related registers. Asserting rst synchronously clears the same state on a clock edge. In the FSM always block, rst | i2c_al is handled as an abort condition, so whenever the bit controller reports arbitration lost, this module clears the current command, stops shifting and loading, deasserts cmd_ack, and returns to ST_IDLE. This behavior is consistent with the specification, where arbitration lost can cancel the active transfer.

Overall, a write-byte flow loads din into sr, optionally generates START, transmits eight data bits in MSB-first order, reads the slave ACK/NACK bit and stores it in ack_out, optionally generates STOP, and finally pulses cmd_ack. A read-byte flow optionally generates START, performs eight READ operations, shifts the sampled bits into sr, sends the master ACK/NACK bit from ack_in, optionally generates STOP, and then pulses cmd_ack; at that point the received byte is available on dout. A STOP-only flow is started when go is triggered by stop, directly issues a STOP command, waits for completion, returns to idle, and pulses cmd_ack.

When reconstructing or maintaining this module, the port directions, widths, reset polarities, always-block sensitivity lists, go expression, FSM priority, and cmd_ack timing should be preserved. In particular, the ST_IDLE decode priority of start > read > write > stop must remain unchanged, the rst | i2c_al abort behavior must be retained, the difference between write-transfer slave ACK/NACK sampling and read-transfer master ACK/NACK driving must be preserved, and the connection to i2c_master_bit_ctrl must remain intact because SCL/SDA timing, bus busy detection, arbitration-lost detection, and bit-command completion all depend on that lower-level controller.

Input ports:
    clk: Master clock. All sequential logic in this byte controller updates on the rising edge of `clk`.
    rst: Synchronous active-high reset. When asserted, the shift register, bit counter, FSM state, command outputs, `cmd_ack`, and `ack_out` are reset to their idle values.
    nReset: Asynchronous active-low reset. When deasserted low, the sequential state is reset immediately, independent of `clk`.
    ena: I2C core enable input passed through to the instantiated bit controller. This byte controller does not directly gate `go` with `ena`; the bit-level behavior is controlled inside `i2c_master_bit_ctrl`.
    clk_cnt[15:0]: SCL timing/prescale count input passed to the bit controller. In this source it is commented as `4x SCL`, and is used by the lower-level bit controller for I2C bit timing.
    start: Request to generate a START or repeated START condition before the byte operation. In `ST_IDLE`, if `go` is true and `start` is asserted, the FSM first issues `I2C_CMD_START`. After the START completes, the FSM continues with READ if `read` is asserted, otherwise with WRITE.
    stop: Request to generate a STOP condition. If asserted together with a read or write operation, STOP is generated after the byte transfer and ACK/NACK phase. If `stop` is the only active operation request, the FSM can issue a STOP command directly from `ST_IDLE`.
    read: Request to read one byte from the I2C bus. The byte controller issues eight bit-level READ commands, shifts sampled bits from `core_rxd` into the shift register, then sends the master ACK/NACK bit using `ack_in`.
    write: Request to write one byte to the I2C bus. The byte controller loads `din` into the shift register, sends eight bits MSB-first through `core_txd`, then reads the slave ACK/NACK bit.

    din[7:0]: Input byte loaded into the internal shift register when a byte command starts. During write operations, this byte is transmitted MSB-first.
    scl_i: SCL pad input from the external I2C bus, passed to the bit controller.
    sda_i: SDA pad input from the external I2C bus, passed to the bit controller.

Processing Flow:

When the module is idle, a byte-level operation is launched only when `go` is asserted, where `go = (read | write | stop) & ~cmd_ack`. This means that a read, write, or stop request must be active, and the module must not currently be asserting the completion pulse. A standalone `start` request does not launch an operation by itself; instead, `start` is used to prepend a START or repeated START condition to a read or write sequence.

Once a command is accepted in `ST_IDLE`, the module loads `din` into the internal shift register `sr` and initializes the bit counter `dcnt` to 7. If `start` is asserted, the FSM first issues `I2C_CMD_START` to the bit controller. After the bit controller acknowledges completion through `core_ack`, the byte controller continues with either a read or write sequence depending on the active command inputs. If `start` is not asserted, the FSM proceeds directly to READ, WRITE, or STOP according to the `ST_IDLE` priority order.

During a write operation, the module sends the contents of `sr` to the bit controller one bit at a time in MSB-first order. `core_txd` defaults to `sr[7]`, and after each completed bit-level WRITE command the shift register advances to the next bit. When the bit counter reaches zero, all eight data bits have been transmitted, and the FSM enters the ACK phase. In this phase, the byte controller issues a bit-level READ command so that the slave-driven ACK/NACK bit can be sampled from `core_rxd` and stored in `ack_out`.

During a read operation, the module repeatedly issues bit-level READ commands to the bit controller. Each completed READ returns one sampled bit on `core_rxd`, and the byte controller shifts that bit into the internal shift register. After eight bits have been received, the FSM enters the ACK phase. In this phase, the byte controller issues a bit-level WRITE command and drives `ack_in` through `core_txd`, allowing the master to send ACK or NACK to the slave.

After the ACK phase, the FSM checks `stop`. If `stop` is asserted, the module issues `I2C_CMD_STOP` and waits for the bit controller to acknowledge that the STOP condition has completed. Only then does it assert `cmd_ack`. If `stop` is not asserted, the FSM returns directly to idle after the ACK phase and asserts `cmd_ack` for one clock cycle. This ensures that the upper-level controller sees command completion only after the requested byte sequence, including any requested STOP condition, has fully completed.

If arbitration is lost, as indicated by `i2c_al`, the byte controller aborts the current operation, clears the active command/control state, and returns to `ST_IDLE`. This prevents the byte-level FSM from continuing to issue bit-controller commands after the lower-level controller has detected that the master no longer owns the bus.
