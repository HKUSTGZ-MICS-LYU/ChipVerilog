The or1200_genpc module is the program-counter generation block of the OR1200 processor. It computes the next instruction fetch address for sequential execution, direct jumps, register jumps, branch-and-link operations, conditional branches, exception entry, exception return, and software-directed PC writes through the SPR path. It also drives the processor-side interface toward the instruction cache or instruction-fetch subsystem, including the fetch address, request signal, byte select, and instruction tag.

Internally, the module maintains a registered program counter named pcreg. This register stores the PC in word-address form, using bits [31:2]. The combinational signal pc represents the next full 32-bit byte address to be sent to the instruction-fetch interface or written back into pcreg. Sequential execution is generated by incrementing pcreg by one word and appending two zero low bits.

The main PC-selection logic is controlled by the combined condition {spr_pc_we, except_start, branch_op}. A software PC write through spr_pc_we has the highest effective priority. When spr_pc_we is asserted, the next PC is taken directly from spr_dat_i, regardless of the current branch operation or exception-start signal. In this case, the internal PC register is also updated with spr_dat_i[31:2] on the next active clock edge.

If there is no SPR PC write and except_start is asserted, the module generates an exception-vector address. This address is formed from the selected exception prefix, the exception type, and the fixed exception-vector low bits. The except_prefix signal selects between the two configured exception-vector high-address prefixes. This exception address becomes the next pc, and the branch operation is ignored for this cycle.

When neither spr_pc_we nor except_start is asserted, the module selects the next PC according to branch_op. For NOP, the next PC is the sequential address pcreg + 1. For J, the target is taken from branch_addrofs. For JR, the target is taken from lr_restor. For BAL, the target is computed as binsn_addr + branch_addrofs. For BF, the branch target is selected only when flag is set; otherwise the sequential address is selected. For BNF, the branch target is selected only when flag is clear; otherwise the sequential address is selected. For RFE, the next PC is taken from epcr.

The taken output is generated by a separate combinational block using the same high-level selection inputs. It indicates whether the current branch, jump, exception entry, or exception return is considered a taken control-flow operation. Unconditional jumps, branch-and-link, register jumps, exception returns, and exception entry set taken to one. Conditional branches set taken only when their condition is satisfied. A NOP operation clears taken. Importantly, an SPR PC write does not set taken in this implementation, even though it can change the PC.

The instruction-fetch address output icpu_adr_o is not always equal to the newly computed pc. During retry or refetch conditions, the module may resend the current instruction address instead of issuing the newly computed address. Specifically, if no_more_dslot, except_start, and spr_pc_we are all deasserted, and either icpu_rty_i or genpc_refetch is asserted, icpu_adr_o is driven from icpu_adr_i. In all other cases, icpu_adr_o is driven from the newly computed pc. This allows the instruction-fetch interface to retry or refetch the same address unless a higher-priority redirection condition occurs.

The instruction-fetch request signal icpu_cycstb_o is controlled only by genpc_freeze in the active implementation. It is asserted whenever genpc_freeze is deasserted and cleared whenever genpc_freeze is asserted. The byte-select output icpu_sel_o is fixed to 4'b1111, meaning that all four byte lanes are selected. The instruction tag output icpu_tag_o is fixed to the normal instruction-fetch tag value `OR1200_ITAG_NI.

The genpc_refetch_r register stores a one-cycle registered copy of genpc_refetch. It is reset to zero on reset, set when genpc_refetch is asserted, and cleared otherwise. However, in the active logic of this implementation, genpc_refetch_r does not affect icpu_adr_o, icpu_cycstb_o, or pcreg. It is only relevant to older control alternatives that remain in the code as comments.

The genpc_stop_prefetch input is also not used by the active implementation. Although it appears in a commented-out alternative expression for icpu_cycstb_o, it has no effect on the current module behavior. Therefore, it should not be described as actively suppressing prefetch requests in this version of the code.

The pcreg register is updated on the rising edge of clk or asynchronously reset by rst. On reset, it is initialized to the reset exception-vector address minus one word, stored in word-address form. This allows the following normal sequential PC update to produce the actual reset exception-vector address. After reset, spr_pc_we has the highest update priority and directly loads spr_dat_i[31:2] into pcreg.

If there is no reset and no SPR PC write, pcreg is updated with pc[31:2] when no_more_dslot is asserted, when except_start is asserted, or during normal execution when the PC generation stage is not frozen, the instruction interface is not retrying, and no refetch is requested. In other words, ordinary sequential PC advancement is blocked by genpc_freeze, icpu_rty_i, or genpc_refetch, but no_more_dslot and except_start can still force the PC register to update.

Overall, or1200_genpc is responsible for deciding the next instruction fetch address and controlling when that address is submitted to the instruction-fetch subsystem. It does not decide whether an exception should occur, nor does it store fetched instructions. Its role is to translate branch, jump, exception, return, retry, refetch, freeze, and SPR-write controls into a concrete fetch address, a branch-taken indication, and the corresponding instruction-fetch interface signals.

module or1200_genpc(
    // Clock and reset
    input clk,
    input rst,

    // External i/f to IC
    output [31:0] icpu_adr_o,
    output icpu_cycstb_o,
    output [3:0] icpu_sel_o,
    output [3:0] icpu_tag_o,
    input icpu_rty_i,
    input [31:0] icpu_adr_i,

    // Internal i/f
    input [2:0] branch_op,
    input [3:0] except_type,
    input except_prefix,
    input [31:2] branch_addrofs,
    input [31:0] lr_restor,
    input flag,
    output taken,
    input except_start,
    input [31:2] binsn_addr,
    input [31:0] epcr,
    input [31:0] spr_dat_i,
    input spr_pc_we,
    input genpc_refetch,
    input genpc_freeze,
    input genpc_stop_prefetch,
    input no_more_dslot
);

Input Ports:
    clk: Main clock signal. Sequential state inside this module is updated on its rising edge.
    rst: Asynchronous reset signal. On reset, pcreg is initialized to the reset exception vector address minus 4, shifted right by 2. This allows the next normal PC update to reach the actual reset entry address.
    icpu_rty_i: Retry signal from the instruction-side interface. When this signal is asserted, the current fetch request needs to be retried, and the module usually preserves and re-outputs the current address.
    icpu_adr_i[31:0]: Current address returned or held by the instruction-side interface. When icpu_rty_i or genpc_refetch is asserted, and no_more_dslot, except_start, and spr_pc_we are all deasserted, this address is re-output on icpu_adr_o so that the same fetch address can be resent.
    branch_op[2:0]: Branch/jump operation selector. It indicates whether the current control-flow operation is sequential execution, direct jump, register jump, branch-and-link, conditional branch, return from exception, and so on.
    except_type[3:0]: Encoded exception type. It is used to generate the corresponding exception vector address when except_start is asserted.
    except_prefix: Exception-vector high-address prefix selector. It selects whether the exception vector is located in the EPH0 region or the EPH1 region.
    branch_addrofs[31:2]: Branch or jump target offset/address field. For a direct jump J, it is used directly as the target word address. For BAL, BF, and BNF, it is added to binsn_addr to form the branch target word address.
    lr_restor[31:0]: Jump target address used by the JR operation. In the current code, this signal is used only for OR1200_BRANCHOP_JR; it is not used for RFE.
    flag: Condition flag used for conditional branches. BF branches when flag=1, while BNF branches when flag=0.
    except_start: Exception-entry start signal. When asserted, and when there is no higher-priority spr_pc_we, pc is set to the corresponding exception vector address.
    binsn_addr[31:2]: Base address of the branch instruction. It is used by BAL, BF, and BNF, together with branch_addrofs, to generate the branch target address.
    epcr[31:0]: Exception PC register value. It is used by the RFE operation to return to the execution point before the exception.
    spr_dat_i[31:0]: Data provided by the SPR write path. When spr_pc_we is asserted, this value is used directly as the new PC address.
    spr_pc_we: SPR-based PC write request. This signal has the highest priority in both the combinational pc selection logic and the sequential pcreg update logic.
    genpc_refetch: Refetch request. When this signal is asserted, and there is no exception, SPR PC write, or no_more_dslot, icpu_adr_o remains equal to icpu_adr_i, causing the current fetch address to be resent. It also prevents pcreg from advancing during normal PC update conditions.
    genpc_freeze: Freeze control for the PC-generation stage. In the currently active implementation, icpu_cycstb_o = !genpc_freeze, and normal PC updates are also paused when genpc_freeze is asserted.
    genpc_stop_prefetch: This input is not used by the currently active logic. It appears only in a commented-out historical implementation of the icpu_cycstb_o control logic, so it should not be described as suppressing prefetch requests in the current implementation.
    no_more_dslot: Indicates that no more delay-slot instruction should be executed. This signal affects address selection for icpu_adr_o and can also trigger an update of pcreg.

Output Ports:
    icpu_adr_o[31:0]: Fetch address output to the instruction fetch subsystem. It is usually the newly computed pc, but in retry or refetch cases it may remain equal to icpu_adr_i.
    icpu_cycstb_o: Instruction-side access request signal. In the current code, it is directly assigned as !genpc_freeze.
    icpu_sel_o[3:0]: Byte-lane select signal for the instruction-side access. It is fixed to 4'b1111.
    icpu_tag_o[3:0]: Instruction-side access tag. It is fixed to `OR1200_ITAG_NI.
    taken: Control-flow transfer indicator. It indicates whether the current branch, jump, exception entry, or RFE operation is considered taken. Note that when spr_pc_we=1, although pc is set to spr_dat_i, taken is 0 in the code. Therefore, taken is not a general-purpose indicator for all PC modification events.

Internal Signal:
    reg [31:2] pcreg: Internal PC register. It stores the current PC in word-address form.
    reg [31:0] pc[31:0]: Combinationally computed next fetch address. It is represented as a byte address.
    reg taken: Combinationally generated control-flow transfer result.
    reg genpc_refetch_r: One-cycle registered version of genpc_refetch. In the currently active logic, this register does not participate in output control or pcreg update decisions. It is retained only for the commented-out historical control logic.

Processing Flow

The operation of or1200_genpc starts with the combinational generation of the candidate next program counter value. The module evaluates {spr_pc_we, except_start, branch_op} to decide the value of pc. An SPR-based PC write has the highest priority: when spr_pc_we is asserted, pc is set directly to spr_dat_i. If there is no SPR PC write but except_start is asserted, the module redirects execution to the selected exception vector address, which is formed from except_prefix, except_type, and the fixed exception-vector low bits. If neither of these higher-priority redirection conditions is active, the module selects the next PC according to branch_op, covering sequential execution, direct jump, register jump, branch-and-link, conditional branch, and return from exception.

In parallel with the candidate pc calculation, the module also generates the taken signal. This signal indicates whether the current branch, jump, exception entry, or return-from-exception operation is considered a taken control-flow transfer. Unconditional jumps, BAL, JR, RFE, exception entry, and satisfied conditional branches assert taken, while normal sequential execution and unsatisfied conditional branches deassert it. An SPR PC write is a special case: although it redirects pc to spr_dat_i, the code does not treat it as a taken branch, so taken remains deasserted.

After the candidate pc has been generated, the module selects the actual address driven to the instruction-side interface through icpu_adr_o. Under normal conditions, icpu_adr_o outputs the newly computed pc. However, when there is no no_more_dslot, no exception entry, and no SPR PC write, and either icpu_rty_i or genpc_refetch is asserted, the module drives icpu_adr_o with icpu_adr_i instead. This causes the previous or current fetch address to be resent to the instruction-side interface, which supports retry and refetch behavior without advancing to a new address.

The instruction-side request control is handled independently through icpu_cycstb_o. In the current active implementation, this signal is assigned as the inverse of genpc_freeze. Therefore, the module continues to issue instruction-side access requests whenever the PC-generation stage is not frozen. Other possible control schemes involving no_more_dslot, genpc_refetch_r, or genpc_stop_prefetch exist only as commented-out historical alternatives and do not affect the current behavior.

On each rising edge of clk, the module updates its sequential state. The internal PC register pcreg is first subject to asynchronous reset; when rst is asserted, it is initialized to the reset exception vector address minus 4, shifted right by two bits, so that the next normal update reaches the actual reset entry address. If reset is not active and spr_pc_we is asserted, pcreg is loaded with spr_dat_i[31:2]. Otherwise, pcreg is updated with pc[31:2] when no_more_dslot is asserted, when except_start is asserted, or when the normal advance condition is satisfied. The normal advance condition requires the stage not to be frozen and requires that there is no instruction-side retry and no refetch request.

At the same time, the module also updates genpc_refetch_r, which is a one-cycle registered copy of genpc_refetch. It is cleared on reset, set for one cycle when genpc_refetch is asserted, and cleared otherwise. In the current active logic, this registered signal is not used to control either the instruction-side outputs or the pcreg update; it is retained only for compatibility with commented-out historical control logic.
