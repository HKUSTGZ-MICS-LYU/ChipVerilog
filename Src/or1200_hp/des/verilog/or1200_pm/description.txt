The or1200_pm module implements the power-management control logic in the OR1200 processor. It stores and accesses the software-programmable state of the Power Management Register, PMR, through the SPR interface. Based on these register fields, the external PIC wakeup signal pic_wakeup, and the CPU stall signal pm_cpustall, it generates the clock slowdown factor, clock-gating requests for different processor submodules, a global wakeup indication, and a low-voltage request. The module itself does not directly perform actual clock gating or voltage regulation; instead, it outputs control signals for external clock and power-management logic.

When the macro OR1200_PM_IMPLEMENTED is defined, the module implements the actual power-management register logic. It contains the 4-bit register sdf, which stores the clock slow-down factor; the register dme, which represents doze mode enable; the register sme, which represents sleep mode enable; and the register dcge, which stores the dynamic clock-gating enable bit. These registers are updated on the rising edge of clk and are controlled by the active-high asynchronous reset rst. On reset, dcge, sme, dme, and sdf are all cleared to zero, indicating that the module is in the normal operating state and does not request clock slowdown, clock gating, or low-power dynamic gating.

The PMR address select signal is pmr_sel. When OR1200_PM_PARTIAL_DECODING is defined, pmr_sel is generated only by checking whether spr_addr[15:11] equals OR1200_SPRGRP_PM, meaning that only SPR group-level partial decoding is performed. When OR1200_PM_PARTIAL_DECODING is not defined, pmr_sel requires both spr_addr[15:11] to equal OR1200_SPRGRP_PM and spr_addr[10:0] to equal OR1200_PM_OFS_PMR, so the register is selected only when the PMR offset address inside the PM SPR group is accessed.

In the sequential logic, rst has the highest priority. After reset is deasserted, if pmr_sel and spr_write are both asserted, the module writes spr_dat_i[3:0] into sdf, spr_dat_i[4] into dme, spr_dat_i[5] into sme, and spr_dat_i[6] into dcge on the rising edge of the clock. If no PMR write occurs in the current cycle and pic_wakeup is high, the module clears dme and sme on the rising edge of the clock, causing the processor to exit the doze or sleep low-power state. In this case, sdf and dcge retain their previous values. Therefore, the clearing of dme and sme by pic_wakeup has lower priority than a PMR write. If a PMR write and pic_wakeup are asserted in the same clock cycle, the module performs the PMR write and does not perform the wakeup clear operation.

When the macro OR1200_PM_READREGS is defined, the module supports reading the PMR fields through the SPR read path. In this case, spr_dat_o[3:0] returns sdf, spr_dat_o[4] returns dme, spr_dat_o[5] returns sme, and spr_dat_o[6] returns dcge. If OR1200_PM_UNUSED_ZERO is also defined, spr_dat_o[31:7] is driven to zero. If OR1200_PM_READREGS is not defined, this module does not assign spr_dat_o. If OR1200_PM_READREGS is defined but OR1200_PM_UNUSED_ZERO is not defined, this module explicitly drives only spr_dat_o[6:0], while the upper bits spr_dat_o[31:7] are not assigned in this module.

All output control signals of the module are generated by combinational logic. pm_clksd is directly equal to sdf, providing the software-configured clock slowdown factor to external logic. pm_cpu_gate is asserted when either dme or sme is set and pic_wakeup is low, meaning that the module requests the CPU main clock to be gated in doze or sleep mode. If pic_wakeup is high, this gate request is immediately suppressed. pm_dc_gate, pm_ic_gate, pm_dmmu_gate, and pm_immu_gate all directly follow pm_cpu_gate, so the clock-gating requests for the DCache, ICache, DMMU, and IMMU are identical to the CPU main clock-gating request.

The Tick Timer has a different gating condition from the other units. pm_tt_gate is asserted only when sme is set and pic_wakeup is low. Therefore, the Tick Timer is requested to be gated only in sleep mode, not in doze mode alone. pm_wakeup is directly equal to pic_wakeup, and it indicates a PIC wakeup event to external logic, which can use it to remove clock gating or resume system operation. pm_lvolt is equal to pm_cpu_gate | pm_cpustall, so the module requests a lower operating voltage whenever the CPU clock-gating request is active or the external CPU stall signal is active.

It should be noted that although the module implements write and read access to the dcge bit, the current code does not use dcge to generate any gating output. The source code also leaves dynamic clock gating as a TODO item. Therefore, in the current implementation, all actual clock-gating requests are statically determined by dme, sme, and pic_wakeup. The dcge bit is only a PMR control bit that can be stored and read back, but it does not yet affect the module’s output behavior.

When the macro OR1200_PM_IMPLEMENTED is not defined, the module does not implement actual power-management register state, and all power-management outputs fall back to the PM-disabled state. In this case, pm_clksd is fixed at 4'b0, meaning that no clock slowdown is requested. pm_cpu_gate, pm_dc_gate, pm_ic_gate, pm_dmmu_gate, pm_immu_gate, and pm_tt_gate are all fixed at 1'b0, meaning that no clock is requested to be gated. pm_wakeup is fixed at 1'b1, indicating that the external logic is always in a wakeup or de-gated state. pm_lvolt is fixed at 1'b0, meaning that no lower operating voltage is requested.

In the branch where PM is not implemented, the SPR read data is also controlled by macros. If OR1200_PM_READREGS is defined, the module drives spr_dat_o[3:0], spr_dat_o[4], spr_dat_o[5], and spr_dat_o[6] all to zero. If OR1200_PM_UNUSED_ZERO is also defined, spr_dat_o[31:7] is also driven to zero. If the related read-register macros are not defined, the corresponding spr_dat_o bits are not assigned by this module.

Overall, or1200_pm is a power-management control module whose enabled features and read-register behavior are controlled by compile-time macros. Its core state is stored in the PMR fields sdf, dme, sme, and dcge, and its output behavior is determined mainly by these fields together with pic_wakeup and pm_cpustall. The current code supports software configuration of the clock slowdown factor, static clock-gating requests in doze and sleep modes, PIC wakeup-based exit from low-power states, separate Tick Timer gating in sleep mode, and low-voltage requests when the CPU is gated or stalled. However, the dynamic clock-gating control bit dcge has not yet been connected to the actual gating logic.

module or1200_pm(
    // RISC Internal Interface
    input clk,
    input rst,
    input pic_wakeup,
    input spr_write,
    input [31:0] spr_addr,
    input [31:0] spr_dat_i,
    output [31:0] spr_dat_o,

    // Power Management Interface
    output [3:0] pm_clksd,
    input pm_cpustall,
    output pm_dc_gate,
    output pm_ic_gate,
    output pm_dmmu_gate,
    output pm_immu_gate,
    output pm_tt_gate,
    output pm_cpu_gate,
    output pm_wakeup,
    output pm_lvolt
);

Input ports:
    - clk: Primary clock; sequential state in this module updates on its rising edge.
    - rst: Reset input that returns local state elements to their defined reset values.
    - pic_wakeup: Programmable interrupt controller wakeup.
    - spr_write: SPR write strobe for this module.
    - spr_addr[31:0]: SPR address used for register decode.
    - spr_dat_i[31:0]: Write data from the SPR/control path.
    - pm_cpustall: CPU-stall indication used by the power-management block.
Output port:
    - spr_dat_o[31:0]: Read data returned on the SPR bus.
    - pm_clksd[3:0]: Programmable clock-slowdown factor generated by the power-management logic.
    - pm_dc_gate: Data-cache clock-gate request.
    - pm_ic_gate: Instruction-cache clock-gate request.
    - pm_dmmu_gate: DMMU clock-gate request.
    - pm_immu_gate: IMMU clock-gate request.
    - pm_tt_gate: Tick-timer clock-gate request.
    - pm_cpu_gate: CPU clock-gate request.
    - pm_wakeup: Wakeup indication generated by the PM block.
    - pm_lvolt: Low-voltage request generated by the PM block.
Internal reg/wire signals:
    reg [3:0] sdf: Clock slow-down factor from the PM register.
    reg dme: Doze-mode enable bit.
    reg sme: Sleep-mode enable bit.
    reg dcge: Dynamic clock-gating enable bit.
    wire pmr_sel: Power-management register select.

Processing Flow

The processing flow of the or1200_pm module depends first on whether power management is implemented through the OR1200_PM_IMPLEMENTED macro. If this macro is not defined, the module does not maintain any internal PMR state. All clock-gating requests and the low-voltage request are deasserted, the clock slowdown factor is fixed to zero, and pm_wakeup is held high to indicate a permanently wakeup or de-gated state.

When OR1200_PM_IMPLEMENTED is defined, the module first decodes the SPR address to determine whether the PMR is selected. Depending on OR1200_PM_PARTIAL_DECODING, this selection is performed either by checking only the SPR group field spr_addr[15:11], or by checking both the SPR group field and the PMR offset field spr_addr[10:0].

On each rising edge of clk, or immediately when the asynchronous reset rst is asserted, the PMR state is updated according to a fixed priority order. If rst is asserted, the PMR fields sdf, dme, sme, and dcge are cleared to zero. Otherwise, if the PMR is selected and spr_write is asserted, the module loads sdf, dme, sme, and dcge from spr_dat_i[6:0]. If no PMR write occurs and pic_wakeup is asserted, only dme and sme are cleared, while sdf and dcge retain their previous values.

After the PMR state is established, the module generates the power-management outputs through combinational logic. pm_clksd directly reflects sdf. pm_cpu_gate is asserted when either doze mode or sleep mode is enabled and there is no active PIC wakeup. The DCache, ICache, DMMU, and IMMU gate requests directly follow pm_cpu_gate. The Tick Timer gate request is asserted only in sleep mode and only when pic_wakeup is low. The wakeup output directly follows pic_wakeup, and the low-voltage request is asserted when either the CPU gate request or the external CPU stall input is active.

If SPR read support is enabled through OR1200_PM_READREGS, the module also drives the implemented PMR fields onto spr_dat_o[6:0]. The upper unused bits spr_dat_o[31:7] are driven to zero only when OR1200_PM_UNUSED_ZERO is also defined. Otherwise, those bits are not assigned by this module.
