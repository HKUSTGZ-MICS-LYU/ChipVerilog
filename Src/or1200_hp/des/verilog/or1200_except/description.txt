Module or1200_except implements exception recognition and sequencing for the OR1200 CPU pipeline. The source file comment describes this module as handling “Exception recognition and sequencing”. The module collects exception and interrupt sources from the instruction side, data side, system-call/trap logic, timer/interrupt inputs, and debug-stop configuration. It determines which exception should be taken according to a fixed priority order, generates pipeline flush control, saves architectural exception state into EPCR, EEAR, and ESR, and provides SPR-visible PPC/NPC information for debug and control logic.

This module is the central exception-control block for OR1200. It tracks the PC and instruction-side exception flags through the pipeline, aligns exception causes with the instruction PC, handles branch-delay-slot cases, selects the exception type, and starts the multi-cycle flush sequence required before exception-handler execution. The sequential logic is updated on the rising edge of clk, and rst asynchronously resets the module state. After reset, the FSM returns to IDLE, except_type is set to OR1200_EXCEPT_NONE, extend_flush is cleared, EPCR and EEAR are cleared, and ESR is initialized to the implementation-defined reset value {1'b1, {OR1200_SR_WIDTH-2{1'b0}}, 1'b1}.

The module pipelines the instruction fetch PC and instruction-side exception flags from IF to ID, and then from ID to EX. The ID-stage exception flags are {sig_ibuserr, sig_itlbmiss, sig_immufault}. When flushpipe is asserted, the ID and EX pipeline PC/exception-flag registers are cleared. The WB-stage PC is maintained separately in wb_pc, which is updated from ex_pc when wb_freeze is not asserted. There is no separate WB-stage exception-flag pipeline in this module. The ex_dslot, delayed1_ex_dslot, and delayed2_ex_dslot registers track whether the instruction associated with an exception is in or related to a branch delay slot, so that the correct PC can be saved into EPCR. wb_pc is also used for delay-slot exception handling and for SPR reads of PPC.

The module maintains delayed interrupt-enable state in delayed_iee. int_pending is asserted only when sig_int is active, sr[2] is enabled, delayed_iee[2] is set, the EX stage is not frozen, the current instruction is not a taken branch or delay-slot instruction, and sr_we is not asserted in the same cycle. The module also maintains delayed_tee, and the comments state that it is intended to delay tick exception re-enabling after l.rfe; however, in this implementation tick_pending does not use delayed_tee. Instead, tick_pending is asserted when sig_tick is active, sr[1] is enabled, EX is not frozen, the current instruction is not a taken branch or delay-slot instruction, and sr_we is not asserted.

The exception sources are arranged into the 13-bit vector except_trig. This vector is ordered by priority; it is not itself an encoded exception number. Priority resolution is performed later by casex (except_trig) in the exception FSM. From highest to lowest priority, the implemented order is: tick timer exception, external interrupt, instruction TLB miss, instruction MMU fault / instruction page fault, instruction bus error, illegal instruction, alignment exception, data TLB miss, data MMU fault / data page fault, data bus error, range exception, trap, system call

Each exception source is gated by the corresponding bit in du_dsr. When the relevant du_dsr bit is clear, the condition contributes to except_trig and can be taken as a normal exception. When the corresponding du_dsr bit is set, the same condition contributes to except_stop instead, so the debug unit can observe the stop reason. except_stop is also a 13-bit reason vector ordered in the same way as except_trig; it is not a compact encoded value. Trap and syscall are additionally gated by ~ex_freeze.

The abort_ex output is asserted for exception conditions that should prevent normal writeback of the current execute-stage instruction. It is the OR of sig_dbuserr, sig_dmmufault, sig_dtlbmiss, sig_align, and sig_illegal.

The flushpipe signal has three sources: except_flushpipe, pc_we, and extend_flush. except_flushpipe is asserted when any bit of except_trig is set and the exception FSM is currently idle. pc_we also forces a pipeline flush and causes the FSM to enter the flush sequence, but unlike a real exception it does not save ESR/EPCR/EEAR or assign a new except_type. extend_flush is generated by the FSM to keep the pipeline invalidated across multiple cycles of exception sequencing.

The simple combinational outputs are as follows. lr_sav is assigned ex_pc[31:2]. spr_dat_ppc returns wb_pc. spr_dat_npc returns id_pc when ex_void is true, otherwise it returns ex_pc. except_start is a combinational level signal, not a one-cycle pulse; it is asserted whenever except_type is not OR1200_EXCEPT_NONE and extend_flush is active. except_started is also combinational and is defined as extend_flush & except_start.

The exception FSM starts in IDLE. When except_flushpipe is asserted in IDLE, the FSM enters FLU1, asserts extend_flush, latches ESR from to_sr if sr_we is active or otherwise from the current sr, and selects the highest-priority exception by matching except_trig with casex. The selected exception determines except_type and the values written into EPCR and EEAR.

For tick and external interrupt exceptions, EPCR is selected from wb_pc if ex_dslot is active; otherwise the implementation selects id_pc through the delayed delay-slot conditions. For instruction TLB miss, EEAR is set to ex_pc, and EPCR is set to wb_pc in a delay slot or ex_pc otherwise. For instruction page fault / instruction MMU fault, EEAR is set to ex_pc when ex_dslot is active, otherwise it uses the delayed delay-slot PC selection that resolves to id_pc; EPCR follows a similar rule, using wb_pc for an active delay slot. For instruction bus error, EEAR and EPCR are set to wb_pc in a delay slot or ex_pc otherwise. For illegal instruction, EEAR is set to ex_pc, and EPCR is set to wb_pc in a delay slot or ex_pc otherwise. For alignment, data TLB miss, data page fault / data MMU fault, and data bus error, EEAR is set to lsu_addr, while EPCR is set to wb_pc in a delay slot or ex_pc otherwise. For range and syscall exceptions, EPCR uses wb_pc for an active delay slot, otherwise the delayed delay-slot PC selection resolves to id_pc. For trap, EPCR is set to wb_pc in a delay slot or ex_pc otherwise.

After exception recognition, the FSM advances through the flush states. In FLU1, it waits until icpu_ack_i, icpu_err_i, or genpc_freeze is asserted before moving to FLU2. In FLU2, trap exceptions take a shorter path: if trap support is enabled and the current exception type is trap, the FSM returns directly to IDLE, clears extend_flush, clears extend_flush_last, and resets except_type to OR1200_EXCEPT_NONE. Other exceptions continue through FLU3 and FLU4. In FLU4, the FSM moves to FLU5 and deasserts extend_flush. In FLU5, the FSM waits until there is no instruction-fetch stall and the ID stage is not frozen; then it returns to IDLE and clears except_type.

If the FSM is idle and no new exception is being taken, software writes through the SPR interface can update EPCR, EEAR, or ESR. epcr_we writes datain into EPCR. eear_we writes datain into EEAR. esr_we writes {1'b1, datain[14:0]} into ESR, forcing the top bit of ESR to 1.

The ports dcpu_ack_i and dcpu_err_i are declared as inputs, but they are not used in the shown implementation. The register extend_flush_last is declared and cleared in reset and some FSM paths, but in this code it is not set or used to drive other logic. Therefore, they should be described as present but functionally unused in this implementation.

In summary, or1200_except defines the OR1200 exception priority order, aligns exception causes with the correct pipeline PC, handles delay-slot exception PC selection, saves EPCR/EEAR/ESR, produces debug stop vectors through except_stop, and drives the multi-cycle flush sequence that redirects control flow to the selected exception handler.

Processing Flow
1. Pipeline PC and exception flag tracking. On each clock cycle, the module tracks the instruction PC and instruction-side exception flags through the pipeline. The IF-stage PC and instruction-side exception flags are latched into the ID stage when id_freeze is not asserted. They are then propagated into the EX stage when ex_freeze is not asserted. The WB-stage PC is updated from ex_pc when wb_freeze is not asserted. If flushpipe is asserted, the ID and EX PC/exception-flag registers are cleared.
2. Delay-slot tracking. The module tracks whether the EX-stage instruction is in a branch delay slot using ex_dslot, delayed1_ex_dslot, and delayed2_ex_dslot. These signals are later used to determine whether EPCR should save wb_pc, ex_pc, or id_pc.
3. Interrupt and tick pending generation. External interrupts are accepted only when sig_int, sr[2], and delayed_iee[2] are active, and when the pipeline is in a suitable state. Tick exceptions are accepted when sig_tick and sr[1] are active and the pipeline is suitable. Although delayed_tee is maintained, it is not used in the actual tick_pending expression in this implementation.
4. Exception trigger and debug-stop vector generation. The module forms the 13-bit except_trig vector from all exception sources that are allowed to enter normal exception handling. The same exception sources form the 13-bit except_stop vector when the corresponding du_dsr bit requests debug stop behavior instead. These vectors are ordered by exception priority.
5. Flush request generation. If any bit of except_trig is set while the FSM is idle, except_flushpipe is asserted. The final flushpipe output is asserted if any of except_flushpipe, pc_we, or extend_flush is active.
6. Exception recognition in IDLE state. When the FSM is in IDLE and except_flushpipe is asserted, the module latches ESR from to_sr if sr_we is active, otherwise from sr. It then resolves the highest-priority exception by matching except_trig with casex.
7. Exception state saving. After selecting the exception type, the module writes except_type and saves EPCR and/or EEAR according to the exception class. Instruction-side exceptions generally use ex_pc, id_pc, or wb_pc depending on the delay-slot state. Data-side exceptions save lsu_addr into EEAR and save the appropriate instruction PC into EPCR.
8. Flush sequencing. The FSM enters FLU1 and asserts extend_flush. In FLU1, it waits for icpu_ack_i, icpu_err_i, or genpc_freeze, then proceeds through the flush states. Trap exceptions may return to IDLE earlier from FLU2. Other exceptions continue through FLU3, FLU4, and FLU5.
9. Exception handler start indication. While except_type is valid and extend_flush is active, except_start is asserted. except_started is derived combinationally from extend_flush & except_start.
10. Return to IDLE. In FLU5, once if_stall is deasserted and the ID stage is not frozen, the FSM returns to IDLE and clears except_type. At that point the exception sequencing is complete.
11. SPR writes when idle. If no exception is being taken and the FSM remains in IDLE, software writes can update EPCR, EEAR, or ESR through epcr_we, eear_we, and esr_we. A pc_we request also starts the flush sequence, but it does not save exception state or assign an exception type.
