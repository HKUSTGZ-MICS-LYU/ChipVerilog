or1200_sb is a Store Buffer module located between the data Cache/DC-side interface and the BIU-side interface. When OR1200_SB_IMPLEMENTED is enabled, its main function is to locally buffer write transactions issued from the DC side, allowing the upstream side to receive an acknowledgment once the write request has successfully entered the Store Buffer, without waiting for the BIU-side bus transaction to actually complete. This decouples the submission of write requests from their external bus completion timing, thereby reducing stalls caused by store operations in the pipeline or upstream data path.

When the Store Buffer is enabled, the module only buffers write requests. If the current DC-side request satisfies dcsb_cyc_i & dcsb_stb_i & dcsb_we_i, the FIFO is not full, and the local write acknowledgment from the previous cycle is not being held, fifo_wr is asserted. The module then writes {dcsb_sel_i, dcsb_dat_i, dcsb_adr_i} into the Store Buffer FIFO. The FIFO stores the byte-select signals, write data, and address, but does not store control signals such as we, cab, cyc, or stb. Therefore, when the Store Buffer path drives the BIU interface, the module forces the outgoing transaction to be a write by setting sbbiu_we_o to 1'b1, and forces sbbiu_cab_o to 1'b0.

The module uses sel_sb to select whether the BIU-side interface is driven by the Store Buffer or by the current DC-side request through the direct pass-through path. The logic of sel_sb is ~fifo_empty | (fifo_empty & outstanding_store). When the FIFO is not empty, there is a pending store request to be sent, so the Store Buffer path is selected. When the FIFO is empty but outstanding_store is still asserted, a Store Buffer request has already been issued to the BIU and is still waiting for an acknowledgment, so the Store Buffer path must remain selected. Only when the FIFO is empty and there is no outstanding store does the module select the direct pass-through path.

outstanding_store records whether there is a Store Buffer write transaction currently waiting for a BIU response. After reset, this register is cleared. When the BIU returns sbbiu_ack_i, the current outstanding store is considered complete and outstanding_store is cleared. Otherwise, if the Store Buffer path is currently selected or a new write request is written into the FIFO in the current cycle, outstanding_store is set. This logic ensures that the module maintains only one uncompleted Store Buffer write transaction on the BIU side at a time.

fifo_rd is defined as ~outstanding_store, meaning that the FIFO is allowed to provide the next store request only when there is no Store Buffer write transaction currently waiting for a BIU acknowledgment. It should be noted that fifo_rd itself does not explicitly check fifo_empty; whether a valid FIFO entry is actually popped depends on the internal empty-control logic of or1200_sb_fifo. Therefore, fifo_rd is more accurately described as an enable condition indicating that the module is allowed to fetch the next FIFO entry, rather than a complete condition meaning “the FIFO is non-empty and a read is performed.”

The ACK returned to the DC side depends on the currently selected path. When sel_sb is asserted, dcsb_ack_o comes from fifo_wr_ack, indicating that the upstream write request has been accepted locally by the Store Buffer. This ACK is generated by a register: it is asserted in the cycle after fifo_wr successfully writes into the FIFO, and normally remains asserted for only one cycle. In this case, the DC side does not need to wait for the BIU to complete the corresponding store transaction. If the FIFO is full and fifo_wr cannot be asserted, this local ACK will not be generated. When sel_sb is deasserted, the module is on the direct pass-through path, and dcsb_ack_o directly forwards sbbiu_ack_i from the BIU side.

Error responses are also handled differently depending on the selected path. When the Store Buffer path is selected, dcsb_err_o is forced to 1'b0, meaning that write requests buffered through the Store Buffer do not return BIU-side errors to the DC side. When the module is on the direct pass-through path, dcsb_err_o is directly assigned from sbbiu_err_i. The returned data signal dcsb_dat_o is always connected to sbbiu_dat_i, so read data comes from the BIU side.

For read requests, the module itself does not perform buffering. A current DC-side read request, or any other non-buffered request, is passed through to the BIU only when the Store Buffer path is not occupying the BIU-side interface, and its ACK, ERR, and returned data are then obtained from the BIU side. If there is a pending store in the FIFO, or if there is already an outstanding store waiting for a BIU acknowledgment, the BIU-side interface is prioritized for the Store Buffer path. In that case, a new read request is not unconditionally passed through to the BIU immediately, but must wait until the Store Buffer path is released.

When OR1200_SB_IMPLEMENTED is not defined, the module does not instantiate the Store Buffer FIFO and does not use control logic such as outstanding_store or fifo_wr_ack. In this configuration, all dcsb_* request signals are directly connected to the corresponding sbbiu_* output signals, and the BIU-side returned dat, ack, and err signals are directly returned to the DC side. In other words, under this configuration, the module fully degenerates into a direct pass-through connection between the DC and BIU interfaces, without write buffering, early acknowledgment, or error masking.

In summary, when the Store Buffer is enabled, or1200_sb implements a buffering and sequential issuing mechanism for store requests. Write requests first enter the FIFO and are locally acknowledged to the upstream side, and are then sent one by one to the BIU according to the BIU’s acceptance timing. At the same time, non-buffered requests are passed through only when the Store Buffer is not occupying the BIU path. The core implementation of this module consists of the FIFO, the sel_sb path-selection logic, the outstanding_store tracking logic for uncompleted transactions, and the fifo_wr_ack local acknowledgment logic.

Processing Flow

When OR1200_SB_IMPLEMENTED is enabled, the module first checks whether the current DC-side request is a valid write transaction. If dcsb_cyc_i, dcsb_stb_i, and dcsb_we_i are asserted, the FIFO is not full, and no previous local write acknowledgment is being held, fifo_wr is asserted. The request payload {dcsb_sel_i, dcsb_dat_i, dcsb_adr_i} is then written into the Store Buffer FIFO.

After the write request is accepted by the FIFO, fifo_wr_ack is asserted in the following clock cycle. When the Store Buffer path is selected, this signal is returned to the DC side as dcsb_ack_o, indicating that the write request has been accepted locally. This acknowledgment does not mean that the BIU-side write transaction has completed; it only means that the request has successfully entered the Store Buffer.

The BIU-side path selection is controlled by sel_sb. If the FIFO is not empty, or if there is still an outstanding_store waiting for a BIU acknowledgment, the Store Buffer path drives the BIU interface. In this state, the BIU-side address, data, and byte-select signals come from the FIFO output, while sbbiu_we_o is forced to 1'b1 and sbbiu_cab_o is forced to 1'b0.

The outstanding_store register tracks whether a Store Buffer write transaction has been issued to the BIU but has not yet received sbbiu_ack_i. When there is no outstanding store, fifo_rd is asserted, allowing the FIFO to provide the next buffered store request. Once the Store Buffer path is selected or a new write is accepted into the FIFO, outstanding_store is set. When the BIU returns sbbiu_ack_i, the outstanding store is considered complete and outstanding_store is cleared.

If the Store Buffer path is not selected, the module uses the direct pass-through path. In this case, the current DC-side request is forwarded directly to the BIU, and the BIU-side ack, err, and read data are returned directly to the DC side. Therefore, read requests are not buffered by this module; they can pass through only when the Store Buffer is not occupying the BIU-side interface.

When OR1200_SB_IMPLEMENTED is not defined, the above buffering flow is bypassed entirely. The module directly connects DC-side request signals to the BIU side and directly returns BIU-side response signals to the DC side, without FIFO buffering, local write acknowledgment, or Store Buffer error masking.
