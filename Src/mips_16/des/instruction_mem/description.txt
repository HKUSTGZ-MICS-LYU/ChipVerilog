The instruction_mem module is the instruction memory used by the IF_stage of the MIPS_16 processor. According to the MIPS_16 specification, the IF_stage contains the program counter and an asynchronous instruction memory. In the current design, the instruction memory is implemented as a ROM for simulation, and it can later be replaced by an instruction cache or an external instruction memory interface . Therefore, the main function of this module is to provide a 16-bit instruction to the processor according to the current program counter value.

The module receives the current program counter pc from the IF_stage. Although the PC width is defined by the macro `PC_WIDTH, the actual ROM address only uses the lower `INSTR_MEM_ADDR_WIDTH bits of the PC. This address is assigned to the internal signal rom_addr. By using only the lower address bits, the module can keep the external PC interface flexible while allowing the actual instruction memory depth to be controlled by the `INSTR_MEM_ADDR_WIDTH macro.

The instruction output is a 16-bit instruction word. This matches the MIPS_16 architecture, which uses a 16-bit instruction and data width. The instruction fetched from this module is sent to the ID_stage, where it is decoded into opcode, register fields, immediate value, and control signals for the following pipeline stages.

This module provides two different implementations controlled by compilation macros. When USE_SIMULATION_CODE is defined, the module is implemented as a simulation ROM using a Verilog register array. The internal ROM is declared as reg [15:0] rom [2**INSTR_MEM_ADDR_WIDTH-1 : 0], and the instruction is read using a continuous assignment. In this version, the ROM contents are not hardcoded inside the module. Instead, they can be initialized from the testbench, which makes the design convenient for running different simulation programs.

When USE_SIMULATION_CODE is not defined, the module uses a synthesizable ROM-style implementation. In this version, the instruction output is declared as a register and is generated by a combinational case statement based on rom_addr. The code contains a predefined sample program, including instructions such as ADDI, ADD, ST, LD, SUB, and BZ. This sample program corresponds to the basic instruction and RAW hazard protection test described in the specification’s sample program section, where the processor executes arithmetic operations, store/load operations, and a branch instruction .

Although the module includes a clk input, the instruction read behavior is asynchronous in both implementations. The clk signal is present in the interface for consistency with the processor structure, but the instruction output is determined directly by the current ROM address. When the PC changes, the lower bits of the PC select a new ROM location, and the corresponding instruction appears at the instruction output after combinational propagation delay. This behavior is consistent with the specification’s description of the IF_stage instruction memory as asynchronous.


Process Flow

During operation, the IF_stage provides the current program counter value to the instruction_mem module through the pc input. The module extracts the lower `INSTR_MEM_ADDR_WIDTH bits of the PC and uses them as the actual ROM address rom_addr.

In the simulation ROM version, rom_addr directly indexes the internal ROM array. The instruction stored at rom[rom_addr] is continuously assigned to the instruction output. This allows the testbench to load different instruction programs into the ROM before or during simulation.

In the synthesizable ROM version, rom_addr is used as the selector of a combinational case statement. Each ROM address maps to a predefined 16-bit instruction value. If the address does not match a defined program location, the module outputs 16'b0000000000000000, which represents a NOP instruction.

Finally, the selected 16-bit instruction is sent back to the IF_stage and then passed into the ID_stage for decoding. Since the ROM is read asynchronously, no clock edge is required to produce the instruction output; the instruction changes according to the PC value and ROM address.

module instruction_mem		// a rtl simulation rom, rom initial code can be found in the testbench
(
	input					clk,		// asynchronized!!
	input	[`PC_WIDTH-1:0]	pc,
	
	output	[15:0]			instruction
);
