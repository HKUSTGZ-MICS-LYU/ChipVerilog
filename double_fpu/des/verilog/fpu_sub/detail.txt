1. Details
- The module implements double-precision floating-point subtraction using operand magnitude ordering, alignment shifting, significand subtraction, leading-zero normalization, and denormal boundary adjustment.
- `fpu_double` contains the instantiations of the other 6 modules, which are 6 separate source files for the 4 operations, the rounding module, and the exceptions module.
- `fpu_sub` is used both for true subtraction and for sign-converted addition cases that the top level routes into the subtraction datapath.
- Subtraction is similar to addition in that the module calculates the exponent difference between the two operands and then shifts the mantissa of the smaller exponent to the right before subtracting. The effective alignment distance also accounts for the normalized/denormalized boundary via large_norm_small_denorm, exactly as in fpu_add.
- If the FPU operation is addition and one operand is positive while the other is negative, fpu_double routes the operation to the subtraction module.
- The implementation consists of two always blocks: a clocked always block (posedge clk) that implements all pipeline registers, and a separate combinational always block (always @(diff)) that implements the leading-zero priority encoder using an explicit casex statement.

2. Input Decomposition
- For each operand, the sign is bit 63, the exponent is bits 62:52, and the mantissa is bits 51:0.

3. Hidden-Bit Handling
- A hidden leading 1 is used only for normalized numbers (encoded as !large_is_denorm and !small_is_denorm in the minuend and subtrahend construction).
- Denormals use hidden bit 0.
- minuend and subtrahend are 55 bits wide (not 56 as in fpu_add) because subtraction cannot produce a carry above the top integer position, so no overflow guard bit is needed at this stage.

4. Output Encoding
- The output mantissa bundle diff_2[55:0] is formatted as follows:
  - bit 55: reserved leading zero (always 0), present so the bundle width matches the format expected by the rounding stage.
  - bit 54: leading integer position for normalized results.
  - bits 53:2: 52-bit mantissa field candidate.
  - bits 1:0: low-order remainder bits for rounding and inexact detection.
- Sticky information is preserved through the subtra_fraction_enable mechanism: if the small operand is nonzero but its aligned shift result is all zero, subtra_shift_3 is forced to the constant {54'b0, 1'b1} to preserve the inexact indication. This is a fixed constant (subtra_shift_2), not a pipeline stage copy.

5. Required Functional Algorithm

5.1 Magnitude comparison
- The module compares the operands by magnitude, not by sign.
- Compute expa_gt_expb = exponent_a > exponent_b.
- Compute expa_et_expb = exponent_a == exponent_b.
- Compute mana_gtet_manb = mantissa_a >= mantissa_b.
- Compute a_gtet_b = expa_gt_expb | (expa_et_expb & mana_gtet_manb).
- This means operand A is treated as greater-or-equal when its exponent is larger, or when the exponents are equal and its mantissa is greater-or-equal.

5.2 Sign selection
- The module always subtracts the smaller magnitude from the larger magnitude, then assigns the correct sign.
- If A has greater-or-equal magnitude, sign = opa[63].
- Otherwise, sign = (!opb[63]) XOR (fpu_op == 3'b000).
- This rule is necessary because the subtract module is used both for subtraction and for addition-with-opposite-signs.

5.3 Equivalent interpretation
- In the true subtraction case, if |A| < |B|, the result sign is the opposite of operand B's sign.
- In the routed-addition case (fpu_op == 000), if |A| < |B|, the result sign equals operand B's sign.

5.4 Large and small selection
- Using magnitude comparison, select exponent_large, mantissa_large, exponent_small, and mantissa_small, where the large operand is the one with greater-or-equal magnitude.

5.5 Denormal detection and exponent difference
- Compute small_is_denorm = (exponent_small == 0).
- Compute large_is_denorm = (exponent_large == 0).
- Compute large_norm_small_denorm = (small_is_denorm == 1) and (large_is_denorm == 0).
- Compute exponent_diff = exponent_large - exponent_small - large_norm_small_denorm.

5.6 Build subtraction operands
- Construct minuend = {!large_is_denorm, mantissa_large, 2'b00}. (55 bits)
- Construct subtrahend = {!small_is_denorm, mantissa_small, 2'b00}. (55 bits)

5.7 Alignment and sticky preservation
- Right-shift the smaller operand: subtra_shift = subtrahend >> exponent_diff.
- Determine whether the smaller operand is nonzero: small_is_nonzero = (exponent_small > 0) | (|mantissa_small[51:0]).
- Determine whether the shifted value is entirely zero: subtra_shift_nonzero = |subtra_shift[54:0].
- subtra_fraction_enable = small_is_nonzero & !subtra_shift_nonzero.
- If subtra_fraction_enable, set subtra_shift_3 = {54'b0, 1'b1} (the constant subtra_shift_2).
- Otherwise, subtra_shift_3 = subtra_shift.

5.8 Subtraction
- Compute diff = minuend - subtra_shift_3.

5.9 Leading-zero count
- A combinational priority encoder implemented as an explicit casex statement counts leading zeros in the 55-bit diff bus and produces diff_shift.
- The casex maps every possible leading-one position (bit 54 down to bit 0) to a shift count from 0 to 54.
- If diff is exactly zero (all bits zero), diff_shift is set to 55.
- diff_shift is produced combinationally (always @(diff)) and is not clocked; it is registered into diff_shift_2 in the clocked block.

5.10 Renormalization
- Register diff_shift into diff_shift_2.
- Compute diffshift_gt_exponent = diff_shift_2 > exponent_large.
- Compute diffshift_et_55 = diff_shift_2 == 55.
- If diffshift_gt_exponent is false: diff_1 = diff << diff_shift_2; exponent = exponent_large - diff_shift_2.
- If diffshift_gt_exponent is true: diff_1 = diff << exponent_large; exponent = 0.

5.11 Exponent update
- If diffshift_et_55 is true, exponent_2 = 0.
- Otherwise, exponent_2 = exponent.

5.12 Normal-to-denormal final adjustment
- Compute in_norm_out_denorm = (exponent_large > 0) & (exponent == 0).
- If true: diff_2 = {1'b0, diff_1 >> 1}.
- Otherwise: diff_2 = {1'b0, diff_1}.
- This preserves correct encoding when a normalized input pair produces a denormal result.

6. Required Sequential Behavior
- All state updates occur on the rising edge of clk.
- Reset clears all pipeline registers and outputs to zero.
- Subtraction, sign selection, leading-zero registration, exponent update, and output formatting occur only when enable is asserted.
- diff_shift is generated combinationally from diff by the explicit casex priority encoder and is not gated by enable; it is registered into diff_shift_2 inside the clocked enable-gated block.

7. Functional Corner Cases
- Exact cancellation produces diff = 0, diff_shift = 55, diffshift_et_55 = 1, exponent_2 = 0, and a zero mantissa bundle.
- If the smaller operand is nonzero but shifts away entirely before subtraction, subtra_fraction_enable injects a sticky 1 into the low bit of subtra_shift_3.
- If the renormalization shift would drive the exponent below zero (diffshift_gt_exponent = 1), the exponent is clamped at zero and the left shift uses exponent_large instead of diff_shift_2.
- If a normalized input pair produces a denormal result (in_norm_out_denorm), the output bundle is right-shifted one additional bit before being forwarded.
