Module `fpu_sub` implements double-precision floating-point subtraction using operand ordering, alignment shifting, significand subtraction, and normalization.
This module performs the aligned mantissa subtraction stage for double-precision floating-point operations whose effective arithmetic is subtraction. It produces an intermediate sign, exponent, and 56-bit mantissa bundle for later rounding and exception handling.
fpu_sub.v compares operand magnitudes, selects the larger magnitude as the minuend, aligns the smaller operand to the larger exponent, preserves sticky information when alignment discards all lower bits, subtracts the significands, counts leading zeros to renormalize the difference, handles exact zero and denormal underflow cases, computes the final sign, and produces an intermediate result for rounding and exception processing.
This source file implements aligned floating-point subtraction of magnitudes. It compares the two operands, subtracts the smaller magnitude from the larger magnitude, determines the correct sign of the result, normalizes the difference by counting leading zeros, and forwards an extended mantissa/exponent representation to the next stage.

Main function
-------------
The module supports two logical use cases:
- true subtraction, when the effective operation is A - B with same-sign operands
- sign-converted addition cases, when the top level redirects opposite-sign addition into the subtraction datapath

To keep the arithmetic simple, the module always subtracts the smaller magnitude from the larger magnitude and then derives the final sign according to which operand had greater magnitude and which logical operation is being performed.

Description:
This module performs the floating-point subtraction datapath for double-precision operands. It is used for same-sign subtraction and also for cases that the top level converts from opposite-sign addition into a magnitude subtraction. The outputs are the intermediate result sign sign, normalized exponent exponent_2, and 56-bit extended mantissa diff_2, which is passed to the rounding stage rather than directly encoded as the final IEEE-754 result.

The mathematical operation is A - B, but for implementation efficiency the module always subtracts the smaller magnitude from the larger magnitude. If A is smaller than B, the hardware computes B - A and then inverts or adjusts the sign so that the final result is mathematically correct. The document explicitly describes this behavior as a way to simplify the subtraction datapath into a larger-minus-smaller operation followed by sign correction .

As in addition, the operands are aligned before subtraction. The smaller-exponent mantissa is right-shifted so both operands are represented at the same exponent. Normalized numbers include the hidden leading 1, while denormalized numbers do not. After subtraction, the difference is stored in diff, and the number of leading zeros is counted by diff_shift. The result is then left-shifted by that amount, and the exponent is reduced by the same amount, thereby normalizing the output. If the difference is zero, the exponent and mantissa are both driven to zero .

Like the adder, this module outputs two extra low-order remainder bits in addition to the leading bit and 52-bit mantissa. These extra bits determine whether rounding will be performed in the next stage. The least significant remainder bit is formed by OR-ing all bits shifted out during alignment, so sticky information is preserved. All outputs update on the rising edge of the clock, and reset clears all internal registers. NaN, infinity, and invalid-operation cases are not resolved here; they are handled by the exceptions stage.
