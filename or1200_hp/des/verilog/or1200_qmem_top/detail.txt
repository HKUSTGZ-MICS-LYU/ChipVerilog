1. Address-hit detection
- iaddr_qmem_hit is asserted when the instruction address matches the configured instruction QMEM window mask/base.
- daddr_qmem_hit is asserted when the data address matches the configured data QMEM window mask/base.
- If QMEM address support is not configured, the hit signals are hardwired low.

2. Bypass behavior for non-QMEM accesses
- Non-hit instruction transactions pass straight through to icqmem_* outputs.
- Non-hit data transactions pass straight through to dcqmem_* outputs.
- Return data/ack/retry/error/tag are simply forwarded from the downstream cache/external side back to the requester.

3. Local-service behavior for QMEM hits
- For an instruction hit, qmemicpu_dat_o comes from the embedded SRAM output and qmemicpu_ack_o is driven by qmem_iack, which is generated by the FSM.
- For a data hit, qmemdcpu_dat_o comes from the embedded SRAM output and qmemicpu_ack_o is driven by qmem_iack, which is generated by the FSM.
- For data-side hits, qmemdcpu_rty_o is driven as ~qmem_dack, reflecting a simple ready/valid handshake behavior.
- Downstream outputs are driven inactive/zero for accesses that are fully absorbed by QMEM.

4. Embedded memory control signals
- qmem_en is asserted when either a matching instruction request or a matching data request is active.
- qmem_we is asserted only for matching data-side write requests.
- qmem_sel chooses byte lanes, favoring the data side when a data hit is active.
- qmem_di is sourced from the data-side write data.
- qmem_addr selects qmemdmmu_adr_i when a data-side hit is active; otherwise it selects qmemimmu_adr_i.

5. Local arbitration / control FSM
The FSM has states IDLE, STORE, LOAD, and FETCH.
- In IDLE, the module watches for a matching local store, local load, or local instruction fetch.
- On a matching request with qmem_ack, it transitions to the corresponding service state and asserts either qmem_dack or qmem_iack.
- In STORE/LOAD/FETCH, it can remain in the same state for a continuing same-type local request, switch directly to another local service type, or return to IDLE when no local request remains.
- qmem_dack and qmem_iack identify whether the data side or instruction side is being acknowledged.
- The FSM evaluates all request conditions every cycle and may immediately switch to a higher-priority request type
This FSM ensures deterministic local completion behavior for the single embedded SRAM port. Only one of qmem_dack or qmem_iack is asserted at a time

6. Memory macro behavior
- The local SRAM is instantiated as or1200_spram_2048x32.
- Address bits [12:2] index the word location.
- The macro supports clock, reset, chip-enable, write-enable, optional byte-select, optional ack, optional MBIST, data input, and data output.

7. Required functional guarantees
An implementation conforming to this spec shall:
- Detect whether an instruction or data request targets the embedded memory window.
- Service matching requests locally and bypass nonmatching requests to the normal hierarchy.
- Correctly generate local ack/data signals and suppress downstream transactions on local hits.
- Support local stores, local loads, and local instruction fetches through one shared SRAM interface.
- Preserve the architectural distinction between instruction-side and data-side return channels.
