
Module `or1200_qmem_top` implements the OR1200 QMEM local-memory interface path for instruction/data accesses outside cached Wishbone flow.

This module implements optional embedded memory handling (“QMEM”). The source file describes it as “Embedded Memory.” It sits between the MMU/CPU-side request paths and the cache-side/external-memory-side paths. Its job is to detect accesses that fall into configured embedded-memory address windows, service them locally through an internal SRAM, and bypass all other accesses to the normal instruction/data memory hierarchy.

Description:

The module implements the OR1200 QMEM local-memory interface path for instruction/data accesses outside cached Wishbone flow.


This module implements the top-level on-chip fast memory (QMEM) of OR1200, which is used to complete access directly from the local RAM when the instruction access path and data access path hit the on-chip embedded RAM address window; when the QMEM address range is missed, the request is bypassed to the instruction Cache/DC path. The module performs address hit judgment on the command side and data side at the same time, and generates local response `qmem_iack/qmem_dack` through a small arbitration state machine.

The QMEM interface is split into two groups: one group connects IMMU/ICPU and IC, and the other group connects DMMU/DCPU and DC. `qmemimmu_*` and `qmemdmmu_*` represent requests from the upper-layer address translation, `icqmem_*` and `dcqmem_*` are bypass interfaces sent to the downstream Cache. When QMEM implementation is enabled, the module first calculates `iaddr_qmem_hit` and `daddr_qmem_hit` respectively, that is, whether the current instruction address or data address falls into the predefined QMEM address window. When a hit occurs, the access on this side is no longer sent to the IC/DC, but is completed by the on-chip RAM; when a miss occurs, all addresses, controls, data and responses are transparently transmitted to the IC/DC as they are.

In terms of combinational logic, if the instruction side hits QMEM, `qmemicpu_dat_o` takes the local RAM output `qmem_do`, `qmemicpu_ack_o` takes the local response `qmem_iack`, `qmemimmu_rty_o` is always 0, `qmemimmu_err_o` is always 0, and the tag returns 0; at the same time, it is sent to the IC The address, `cycstb`, cache inhibit, byte select and tag are all pressed to 0. Similar processing occurs when the data side hits: the return data comes from `qmem_do`, the response comes from `qmem_dack`, the error is always 0, the tag is always 0, and the request is prevented from continuing to be sent to the DC. If there is a miss, each output will directly follow the return result of the subsequent stage IC/DC. The actual enable of on-chip RAM `qmem_en` is valid when "instruction hit and there is an instruction fetch request" or "data hit and there is a data request"; the write enable `qmem_we` is only valid when the data side hits and the current write operation is. In terms of address selection, if the current data side hits, the data address will be used first, otherwise the instruction address will be used.

In terms of timing, the module includes the status register `state` and two local response registers `qmem_dack` and `qmem_iack`, which are updated on the rising edge of `clk` and have an asynchronous high level reset `rst`. Entering `IDLE` after reset, both responses are cleared. The state machine is essentially a simple arbiter that "determines which side to send ACK to in the next shot based on the current request type." The state includes idle, STORE, LOAD, and FETCH. No matter which state it is currently in, the request will be re-observed every beat according to a fixed priority: data writing takes precedence over data reading, and data reading takes precedence over instruction value acquisition; if the corresponding request exists and the local RAM is ready (`qmem_ack` is valid, if the interface is not defined, it is regarded as constant 1), then switch to the corresponding state and only pull up the response signal on the corresponding side; if there is no local hit request, return to `IDLE` and clear both ACKs. Due to the beat-by-beat observation, continuous local data writing or data reading can remain in the same state and continue to give ACK; once the request type changes, the state machine will switch to a new state in the next beat.

The module instantiates a 2048x32 single-port RAM. The address uses the word address `qmem_addr[12:2]`, the data input comes from `qmemdcpu_dat_i`, and the output is unified to `qmem_do`; if the byte enable or local ACK option is enabled, connect `qmem_sel` and `qmem_ack` respectively. Since there is only one local RAM port, when instructions and data hit at the same time, the module actually assigns the port priority to data access through the above priority level. If QMEM is not enabled at all, the implementation degrades to pure pass-through without any local hit judgment or arbitration.

module or1200_qmem_top(
    // Rst, clk and clock control
    input clk,
    input rst,

`ifdef OR1200_BIST
    // RAM BIST
    input mbist_si_i,
    output mbist_so_o,
    input [`OR1200_MBIST_CTRL_WIDTH - 1:0] mbist_ctrl_i,
`endif

    // QMEM and CPU/IMMU
    input [31:0] qmemimmu_adr_i,
    input qmemimmu_cycstb_i,
    input qmemimmu_ci_i,
    input [3:0] qmemicpu_sel_i,
    input [3:0] qmemicpu_tag_i,
    output [31:0] qmemicpu_dat_o,
    output qmemicpu_ack_o,
    output qmemimmu_rty_o,
    output qmemimmu_err_o,
    output [3:0] qmemimmu_tag_o,

    // QMEM and IC
    output [31:0] icqmem_adr_o,
    output icqmem_cycstb_o,
    output icqmem_ci_o,
    output [3:0] icqmem_sel_o,
    output [3:0] icqmem_tag_o,
    input [31:0] icqmem_dat_i,
    input icqmem_ack_i,
    input icqmem_rty_i,
    input icqmem_err_i,
    input [3:0] icqmem_tag_i,

    // QMEM and CPU/DMMU
    input [31:0] qmemdmmu_adr_i,
    input qmemdmmu_cycstb_i,
    input qmemdmmu_ci_i,
    input qmemdcpu_we_i,
    input [3:0] qmemdcpu_sel_i,
    input [3:0] qmemdcpu_tag_i,
    input [31:0] qmemdcpu_dat_i,
    output [31:0] qmemdcpu_dat_o,
    output qmemdcpu_ack_o,
    output qmemdcpu_rty_o,
    output qmemdmmu_err_o,
    output [3:0] qmemdmmu_tag_o,

    // QMEM and DC
    output [31:0] dcqmem_adr_o,
    output dcqmem_cycstb_o,
    output dcqmem_ci_o,
    output dcqmem_we_o,
    output [3:0] dcqmem_sel_o,
    output [3:0] dcqmem_tag_o,
    output [31:0] dcqmem_dat_o,
    input [31:0] dcqmem_dat_i,
    input dcqmem_ack_i,
    input dcqmem_rty_i,
    input dcqmem_err_i,
    input [3:0] dcqmem_tag_i
);
