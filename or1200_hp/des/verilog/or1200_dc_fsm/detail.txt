1. State Machine
The RTL defines these states:
- OR1200_DCFSM_IDLE
- OR1200_DCFSM_CLOAD
- OR1200_DCFSM_LREFILL3
- OR1200_DCFSM_CSTORE
- OR1200_DCFSM_SREFILL4

A compatible implementation shall preserve the externally visible behavior of these states even if the exact encodings differ.

2. Functional Behavior
2.1 Idle state
When no request is active, the FSM shall remain idle with no bus transaction and no RAM/tag writes.

2.2 Cached load hit
If a load request arrives, the cache is enabled, the access is cacheable, and tagcomp_miss is false:
- first_hit_ack shall assert
- no external refill shall be started
- returned data will come from cache RAM

2.3 Load miss / line refill
If a cacheable load misses:
- the FSM shall save the requested address
- initiate a BIU read burst
- write incoming words into data RAM according to refill position
- update the tag (valid/tag value) once the refill sequence completes
- assert first_miss_ack when the requested data becomes available
- assert burst during burst refill
- The refill counter cnt is initialized to OR1200_DCLS-2 (for load refill) or OR1200_DCLS-1 (for store refill), confirming a cache line of OR1200_DCLS words.

The state names indicate a 4-word cache line. The refill logic shall therefore advance through word positions of the line.

2.4 Cached store handling
For a store in cacheable space, the FSM shall control whether the operation is a hit-side update or requires an external write sequence. dcram_we shall reflect the request byte select mask or line-write behavior required by the state.

2.5 Cache-inhibited / bypass behavior
If dcqmem_ci_i is asserted or the cache is disabled, the FSM/output logic must allow direct BIU access rather than cache-line allocation behavior.

2.6 Error behavior
If biudata_error is received during an outstanding miss/bypass transaction:
- first_miss_err shall assert
- the FSM shall terminate or recover according to the request class without falsely updating tag/data RAM

3. Output Generation Requirements
- dc_addr shall select either the current request address or the saved/refill address depending on state
- biu_read and biu_write shall be mutually consistent with the transaction type
- dcram_we shall indicate which bytes/words are written into cache RAM
- tag_we shall only assert when the line tag/valid bit is intended to be updated
- first_hit_ack and first_miss_ack must be one-shot acknowledgements for the requesting LSU side

4. Implementation Notes
- The cache line size is fixed by this design to 16 bytes = 4 words.
- The FSM is stateful and clocked.
- It relies on an external tag compare result rather than performing compare internally.
- It assumes an external top-level block handles the final datapath selection between DCRAM and BIU data.

5. Implementation Constraints
A compatible implementation shall preserve:
- hit/miss acknowledgement timing semantics
- refill sequencing for a 4-word line
- byte-enable handling for stores
- error signaling behavior
- interaction contract with or1200_dc_top, or1200_dc_ram, and or1200_dc_tag
