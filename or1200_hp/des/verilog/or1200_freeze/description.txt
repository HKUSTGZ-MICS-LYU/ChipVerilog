
Module `or1200_freeze` generates stage freeze/stall controls to maintain pipeline correctness across hazards, waits, and exceptions.

This module generates the processor pipeline freeze/stall signals. The source file explicitly says it is “Freeze logic (stalls CPU pipeline, ifetcher etc.).” It converts multiple back-pressure and control-flow conditions into a coherent set of per-stage freeze signals.

Description:



This module implements OR1200 pipeline freeze and pause control and is the unified generation point for freeze signals at all levels of the processor's front-end/back-end. The module generates `genpc_freeze`, `if_freeze`, `id_freeze`, `ex_freeze` and `wb_freeze` based on conditions such as debugging shutdown, memory access wait, multi-cycle instruction, delay slot forced instruction fetch, MAC unit pause, abnormal termination and flush pipeline request, thereby ensuring that the pipelines at all levels maintain a consistent advancement relationship when the relevant data or control conditions are not met.

In terms of timing, the module contains two timing registers: `flushpipe_r` and `multicycle_cnt`, both updated on the rising edge of `clk` and with asynchronous high-level reset `rst`. After reset, `flushpipe_r` is cleared and `multicycle_cnt` is cleared, indicating that there are no pending flush pipe requests and multi-cycle freezes. `flushpipe_r` only latches the current `flushpipe` when it receives a command-side response or error `icpu_ack_i | icpu_err_i`, thereby aligning the flush pipe request to the time when the instruction fetch is completed; if there is no new `flushpipe` request, `flushpipe_r` will be cleared on subsequent clocks. `multicycle_cnt` is decremented every beat when non-zero; when the count is zero and `multicycle` is non-zero and the execution level is not frozen, the new multicycle length is loaded. Thus `multicycle_freeze` remains in effect throughout the entire period when the count is non-zero.

In combination logic, `genpc_freeze` is determined by the debug shutdown `du_stall` and the registered flush pipe request `flushpipe_r`, which is used to prevent the PC from continuing to advance; `if_freeze` is triggered by `id_freeze` or the extended flush pipe `extend_flush`, so the IF-level freeze condition at least covers the ID-level freeze condition. `id_freeze` is set when the LSU waits, an instruction fetch waits and the LSU has not released the wait, a multi-cycle operation is not completed, a delay slot needs to be forced, a debug shutdown or a MAC stall. `wb_freeze` has the same main condition as `id_freeze`, but additionally contains `abort_ex`, which means that writeback level freezing will give priority to overwriting execution abort scenarios; `ex_freeze` is directly equal to `wb_freeze`, thus ensuring that the execution level will not continue to push forward when writeback level freezes.

This module embodies clear freeze priority and consistency constraints: subsequent-level freezes will not be weaker than those of previous-level dependencies, and execution-level freezes completely follow write-back-level freezes; while the IF/ID stage allows freezing earlier than subsequent stages in some scenarios, thereby inserting NOPs in the pipeline or preventing new instructions from entering. The module itself does not directly save the pipeline data of each stage, but only outputs freezing control. Therefore, all boundary behaviors are reflected in the combination relationship of freezing conditions and the update timing of the two auxiliary registers.

module or1200_freeze(
    // Clock and reset
    input clk,
    input rst,

    // Internal i/f
    input [1:0] multicycle,
    input flushpipe,
    input extend_flush,
    input lsu_stall,
    input if_stall,
    input lsu_unstall,
    input du_stall,
    input mac_stall,
    input force_dslot_fetch,
    input abort_ex,
    output genpc_freeze,
    output if_freeze,
    output id_freeze,
    output ex_freeze,
    output wb_freeze,
    input icpu_ack_i,
    input icpu_err_i
);

Input ports:
    - clk: Primary clock; sequential state in this module updates on its rising edge.
    - rst: Reset input that returns local state elements to their defined reset values.
    - multicycle[1:0]: Multi-cycle operation control value used by the freeze logic.
    - flushpipe: Pipeline flush request.
    - extend_flush: Extended flush control that keeps the pipeline invalidated for multiple cycles.
    - lsu_stall: Load/store-unit stall indication.
    - if_stall: Fetch-stage stall indication.
    - lsu_unstall: Load/store completion indication that releases the pipeline stall.
    - force_dslot_fetch: Control that forces fetching of a branch delay-slot instruction.
    - abort_ex: Indicates that the current execute-stage instruction must be aborted.
    - du_stall: Debug-unit stall request into the pipeline.
    - mac_stall: MAC-unit stall request into the freeze logic.
    - icpu_ack_i: Acknowledge/transfer-complete indication for the CPU-to-instruction-memory interface.
    - icpu_err_i: Error termination indication for the CPU-to-instruction-memory interface.
Output port:
    - genpc_freeze: Freeze control for the program-counter generation stage.
    - if_freeze: Freeze control for the fetch stage.
    - id_freeze: Freeze control for the decode stage.
    - ex_freeze: Freeze control for the execute stage.
    - wb_freeze: Freeze control for the writeback stage.
Internal reg/wire signals:
    wire multicycle_freeze: Freeze asserted while a multicycle op is active.
    reg [1:0] multicycle_cnt: Countdown for the remaining multicycle stalls.
    reg flushpipe_r: One-cycle registered copy of the pipeline flush request.
