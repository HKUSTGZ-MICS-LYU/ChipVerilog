1. Internal state
The FSM uses:
- state: at least IDLE, CFETCH, and LREFILL3 states
- saved_addr_r: current address/line pointer
- cnt: refill word counter
- hitmiss_eval: true while the first returned word is still being evaluated for hit/miss
- load: indicates refill/load in progress
- cache_inhibit: latched copy of cache-inhibit status for the current transaction

2. Core behavioral rules
2.1 Write-enable generation
- icram_we = 4 copies of (biu_read & biudata_valid & !cache_inhibit)
- tag_we = biu_read & biudata_valid & !cache_inhibit
Thus returned words are written into cache RAM and tag RAM only for cacheable transactions.

2.2 IDLE state
When ic_en and icqmem_cycstb_i are asserted, the FSM enters CFETCH, saves the start address, sets hitmiss_eval, sets load, clears cache_inhibit, and begins processing the fetch.
If there is no active fetch, it stays idle and clears transient control flags.

2.3 CFETCH state
This state serves two purposes:
- complete a cache hit immediately if tag comparison succeeds;
- begin external refill processing if the access misses.
Detailed behavior:
- If a cache-inhibited access is detected, cache_inhibit is latched.
- While hitmiss_eval is active, the upper address bits of saved_addr_r are refreshed from start_addr.
- If the fetch is aborted, or an external error occurs, or a cache-inhibited access returns data, the FSM returns to IDLE.
- If tagcomp_miss and biudata_valid are both true, the first fetch word of a missed line has arrived; the FSM moves to LREFILL3, increments the line word index, clears hitmiss_eval, and sets cnt to the remaining words in the line.
- If there is no miss and the page is cacheable, the hit is completed immediately and the FSM effectively returns to/behaves as idle for the next access.

2.4 LREFILL3 state
This state finishes the refill of the remaining cache line words.
- On each valid returned word while cnt is nonzero, cnt decrements and saved_addr_r[3:2] increments.
- On the last valid returned word, the FSM returns to IDLE, restores saved_addr_r to start_addr, and clears transient control flags.

3. CPU completion semantics
The module generates three important completion conditions.
- first_hit_ack: first word was already in cache and can be consumed immediately.
- first_miss_ack: first word of a missed line arrived from memory.
- first_miss_err: first word of a missed line terminated with an error.
These signals allow the CPU to proceed as soon as the requested instruction word is available, while the cache may continue refilling the rest of the line.

4. Burst semantics
burst is asserted for miss/refill sequences so the external BIU can request a line burst. It is true during the miss-handling portion of CFETCH and throughout LREFILL3.

5. Address handling
saved_addr is the address used for RAM writes and subsequent burst-word placement. The implementation currently forwards saved_addr_r. A reimplementation must preserve the line-word increment behavior so each returned burst word is written into the correct position in the cache line.

6. Summary
or1200_ic_fsm.v is the control brain of the instruction cache. It decides whether a fetch is a hit, whether to fetch from external memory, when to acknowledge the CPU, and how to refill the cache line word by word.
