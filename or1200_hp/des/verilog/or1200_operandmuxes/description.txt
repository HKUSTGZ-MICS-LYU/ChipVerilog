
Module `or1200_operandmuxes` selects ALU operand sources from register file data, immediates, and forwarding paths.

This module is the operand-selection block for the execution stage. The source describes it as “Mux for two register file read operands.” It also contains small holding registers so operand values are preserved correctly across certain freeze scenarios.

Description:

The module selects ALU operand sources from register file data, immediates, and forwarding paths.

This module implements two operand registers at the execution level and their forward/immediate selection logic. It is located between the register file read port and the execution stage. It is responsible for selecting the two operands actually used by this instruction from the register file output, execution level forward results, write-back level forward results or immediate data according to the selection signals `sel_a` and `sel_b`, and saves the selected value when the pipeline is frozen to prevent the execution level operands from being destroyed due to changes in the read port during the ID level pause.

The module updates `operand_a`, `operand_b` and auxiliary flags `saved_a`, `saved_b` on the rising edge of `clk` with an asynchronous high reset `rst`. After reset, the two operand registers are cleared and the save flag is cleared. Under normal circumstances, as long as the execution level is not frozen `!ex_freeze` and the corresponding operand is not in the "saved for release" state, the combined selection result `muxed_a/muxed_b` will be loaded into `operand_a/operand_b`. If a scenario occurs where "the execution level can advance, but the ID level is frozen and the operand has not been saved", the module will load the current combination result into the register at this time and set `saved_a/saved_b` to lock the operand of this instruction. Later, when the ID level freeze is lifted and the execution level can continue to advance, the save flag is cleared, allowing new operands to be loaded.

The combination selection logic is divided into two parts. For operand A, `sel_a` only chooses between the register file value `rf_dataa`, execution-level forward `ex_forw`, and write-back-level forward `wb_forw`: the priority is uniquely determined by the `sel_a` encoding, with no additional coverage. For operand B, in addition to the above three sources, immediate data `simm` is also supported; when `sel_b` selects immediate data, `muxed_b` directly takes `simm`. The output `muxed_b` is also exported separately, so that subsequent units can obtain the "combined selected B source" at the same time, not just the `operand_b` that has been clocked.

The key point of this module is freezing processing: it is not a simple combination multiplexer, but saves the operands once in a special window where the ID is frozen and the EX is not frozen, so as to avoid changes in subsequent register file reading data. In terms of priority, reset has the highest priority; in the working state, only `!ex_freeze` is allowed to update the register; once the save flag is set, it will prevent subsequent repeated overwriting and will not be cleared until the ID freeze is lifted.

module or1200_operandmuxes(
    // Clock and reset
    input clk,
    input rst,

    // Internal i/f
    input id_freeze,
    input ex_freeze,
    input [31:0] rf_dataa,
    input [31:0] rf_datab,
    input [31:0] ex_forw,
    input [31:0] wb_forw,
    input [31:0] simm,
    input [1:0] sel_a,
    input [1:0] sel_b,
    output [31:0] operand_a,
    output [31:0] operand_b,
    output [31:0] muxed_b
);

Input ports:
    - clk: Primary clock; sequential state in this module updates on its rising edge.
    - rst: Reset input that returns local state elements to their defined reset values.
    - id_freeze: Freeze control for the decode stage.
    - ex_freeze: Freeze control for the execute stage.
    - rf_dataa[31:0]: Register-file source data A.
    - rf_datab[31:0]: Register-file source data B.
    - ex_forw[31:0]: Forwarded execute-stage result used for operand bypassing.
    - wb_forw[31:0]: Forwarded writeback result used for operand bypassing.
    - simm[31:0]: Expanded immediate operand supplied to execute-stage muxing.
    - sel_a[1:0]: Source selector for execute-stage operand A.
    - sel_b[1:0]: Source selector for execute-stage operand B.
Output port:
    - operand_a[31:0]: Registered execute-stage operand A.
    - operand_b[31:0]: Registered execute-stage operand B.
    - muxed_b[31:0]: Combinationally selected operand-B value before execute-stage registration.
Internal reg/wire signals:
    reg [31:0] operand_a: Selected operand A value.
    reg [31:0] operand_b: Selected operand B value.
    reg [31:0] muxed_a: Muxed operand-A value.
    reg [31:0] muxed_b: Muxed operand-B value.
    reg saved_a: Saved A.
    reg saved_b: Saved B.
