
Module `or1200_du` implements the debug unit, including breakpoint/watchpoint control and debug interaction with pipeline execution.

This module is the OR1200 debug unit. The source file itself describes it as the “Basic OR1200 debug unit.” It bridges three worlds:
- internal processor activity (instruction fetch, LSU accesses, executed instruction, PC, exceptions);
- the SPR interface used to configure debug registers;
- an external debug port used to stall the processor and read/write data.
A correct implementation must provide run-control, breakpoint/watchpoint support, exception-stop handling, and debug register storage.

The module monitors instruction and data-side activity and decides whether execution should continue or stop. When a stop condition is met, it asserts debug breakpoint/stall related outputs and records the reason in internal debug registers. It also exposes a software-visible register bank through SPR reads/writes and a hardware-visible debug interface through dbg_* signals.

Description:

The module implements the debug unit, including breakpoint/watchpoint control and debug interaction with pipeline execution.


This module is the debug unit of OR1200. It is responsible for connecting the external debugging port and the internal CPU debugging interface, and implements debugging registers, breakpoint/observation point comparison, stop reason recording, hardware breakpoint triggering, and access control to CPU SPR/internal registers. The module uses the rising edge of clk to update the internal debugging registers and event status, and rst asynchronously resets these statuses; when the debugging unit is not implemented, the module degenerates into a set of simple transparent transmission and constant value output.

At the most basic transparent transmission level, du_stall is directly equal to the external dbg_stall_i, so the external debugger can unconditionally request a CPU shutdown; du_addr, du_dat_o, du_read, and du_write are respectively generated by the combination of dbg_adr_i, dbg_dat_i, dbg_stb_i, and dbg_we_i, and are used to directly send external debugging access to the CPU's internal debugging interface. dbg_dat_o returns du_dat_i directly. The response dbg_ack_o of the external debugging port just delays the output of dbg_stb_i by one clock cycle, so each external debugging read and write will be responded to in the next beat. The priority of this response logic is simple: clear to 0 on reset, otherwise each beat reflects the dbg_stb_i of the previous beat.

Under complete debugging implementation, the module contains DMR1/DMR2 (Debug Mode Register), DSR (Debug Stop Mask/Enable Register), DRR (Debug Reason Register), multiple DVRs (Debug Compare Value Register), DCR (Debug Compare Control Register) and DWCR (Observation Point Counter Register). These registers are accessed through the SPR space, and whether they are actually implemented is determined by compile-time macros; unimplemented registers are read as fixed values, and writing is invalid. The module generates the select signal of each register based on the combination of spr_cs and spr_addr, and then completes writing on the clock edge. On reset, each debug register is set to an implementation-defined initial value, usually all 0s or a macro-defined default debug configuration; only hit SPR write accesses can then update the corresponding register.

Functionally, the debug unit continuously observes the instruction fetch status, branch information during execution, EX-level instructions, current PC, memory access address, memory access data, and exception stop vector du_except. According to the comparison value saved in the DVR and the comparison type/enable condition defined in the DCR, the module can generate observation point hits for events such as fetch address, load/store address, load/store data, etc. Hit observation points, abnormal stop requests, single-step mode, external event triggers, etc. are then determined by the DMR/DSR configuration whether to only record the cause, stop, or trigger the hardware breakpoint output. du_hwbkpt is the comprehensive output of "should trigger a trap/hardware breakpoint to the CPU". DRR will record the reason bit that caused the current debugging to stop, and DSR provides masking/selection function for which exceptions or events should be stopped. The module also exports dbg_lss_o, dbg_is_o, dbg_wp_o and dbg_bp_o to reflect the LSU status, fetch status, observation point hit status and breakpoint status.

Therefore, the essence of this module is a programmable debugging event monitoring and access bridge unit: on the one hand, it converts the access request of the external debugger to internal reading and writing of the CPU; on the other hand, it uses a set of programmable comparison registers to monitor the instruction flow, data flow and exceptions, and when the conditions are met, the CPU stops, records the reason or triggers hardware breakpoints.

module or1200_du(
    // RISC Internal Interface
    input clk,
    input rst,
    input dcpu_cycstb_i,
    input dcpu_we_i,
    input [31:0] dcpu_adr_i,
    input [31:0] dcpu_dat_lsu,
    input [31:0] dcpu_dat_dc,
    input [0:0] icpu_cycstb_i,
    input ex_freeze,
    input [2:0] branch_op,
    input [31:0] ex_insn,
    input [31:0] id_pc,
    input [31:0] spr_dat_npc,
    input [31:0] rf_dataw,
    output [13:0] du_dsr,
    output du_stall,
    output [31:0] du_addr,
    input [31:0] du_dat_i,
    output [31:0] du_dat_o,
    output du_read,
    output du_write,
    input [12:0] du_except,
    output du_hwbkpt,
    input spr_cs,
    input spr_write,
    input [31:0] spr_addr,
    input [31:0] spr_dat_i,
    output [31:0] spr_dat_o,

    // External Debug Interface
    input dbg_stall_i,
    input dbg_ewt_i,
    output [3:0] dbg_lss_o,
    output [1:0] dbg_is_o,
    output [10:0] dbg_wp_o,
    output dbg_bp_o,
    input dbg_stb_i,
    input dbg_we_i,
    input [31:0] dbg_adr_i,
    input [31:0] dbg_dat_i,
    output [31:0] dbg_dat_o,
    output dbg_ack_o
);
