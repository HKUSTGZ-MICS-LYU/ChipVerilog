
Module `or1200_top` is the top-level OR1200 wrapper that connects CPU core, caches/MMUs, debug, and external Wishbone interfaces.

This module is the top-level integration point of the OR1200 processor subsystem. It combines the CPU core with the instruction-side and data-side WISHBONE bus interfaces, MMUs, caches, embedded QMEM support, store buffer, debug unit, interrupt controller, tick timer, and power-management block. In the hyper-pipelined project, this is the module that preserves the system-level OR1200 interface while the internal core may be transformed to use additional clock domains and memory steering. The PDF states that the resulting hyper pipelined OR1200 core keeps “the same inputs and outputs plus the new clk_i_cml_* clocks”, and that “the CMLS (core multiplier level selector) signal is routed to the memories.”

Description:

The module is the top-level OR1200 wrapper that connects CPU core, caches/MMUs, debug, and external Wishbone interfaces.

- Using this file as top level, the timing of this single clock indicates the performance of the hyper pipelined OR1200 core.
- If no false path is reported, the individual clocks can be merged with the original clock when the hyper pipelined OR1200 core is instantiated.
- For that an OR1200_core_cm[CMF]_top.vhd file is delivered.

This module is the top-level integrated module of the OR1200 processor system and is used to connect the CPU core, instruction and data storage access paths, IMMU/DMMU, instruction Cache, on-chip fast memory, Store Buffer, Wishbone BIU, debug unit, PIC, Tick Timer and power management unit into a complete system. The module itself does not undertake complex local control algorithms. Its main responsibility is to instantiate each sub-module and complete the connection and distribution of clock, reset, bus and SPR access paths.

The system works under the main clock `clk_i`, and the reset input is `rst_i`. In this implementation, the Wishbone clock and reset do not run independently, but are merged directly with the main processor clock/reset, so the instruction and data bus interfaces are in the same clock domain as the CPU, which is consistent with the description in the specification that "the Wishbone clock input is merged with the processor clock for simplicity." The top level itself has no explicit local registers or state machines, and all timing states are updated by its lower-level modules on the rising edge of their respective `clk_i`; the top level only distributes reset and control signals, so the reset priority is reflected within each instance, rather than being processed twice by the top level.

From the perspective of the data path, the CPU's instruction access request first enters the IMMU, then enters the top level of QMEM for on-chip storage hit determination, then enters the instruction Cache, and finally accesses the external bus through the instruction Wishbone BIU. The CPU's data memory access request first passes through DMMU, then enters QMEM, then to the data cache, and is sent to the external bus through the Store Buffer and data Wishbone BIU. In this way, the top layer clearly distinguishes the instruction path and the data path, and adds a store buffer to the data path to improve write transaction throughput.

The top level is also responsible for group-level distribution of SPR access. The CPU uniformly generates `spr_addr`, `spr_dat_cpu`, `spr_cs` and `spr_we`, and the top layer is sent to the IMMU, IC, DMMU, DC, debugging unit, PIC, Tick Timer and power management unit respectively according to the one-hot group bit of `spr_cs`. The `spr_dat_*` returned by the corresponding submodule is then sent back to the SPR control unit or CPU for use. This route is completely combined decoding and has no local storage, so the access path switches in real time as `spr_cs` and `spr_addr` change.

Interrupts and debugging are also uniformly accessed at the top level. The external interrupt input `pic_ints_i` is sent to the PIC, and the PIC outputs the total interrupt request `sig_int` and the wake-up signal `pic_wakeup`; the Tick Timer generates `sig_tick`; both are sent to the CPU. The debug interfaces `dbg_*` are connected to the debug unit, which can impose shutdown, read and write registers/memory, and exception control on the CPU. The power management unit receives `pic_wakeup` and CPU-related controls, and outputs various gate control and wake-up signals. If BIST is enabled, the top layer also connects the MBIST chains of IMMU, IC, QMEM, DMMU, and DC in series.

For external Wishbone ports, `iwb_*` carries instruction access and `dwb_*` carries data access; `ack/err/rty` and other handshake signals are interpreted by the corresponding BIU and fed back to the internal storage path. There is no arbitration or caching done here at the top level, so the timing behavior of these interfaces depends entirely on the individual BIUs and downstream modules. In general, this module implements a "purely connected" top layer: responsible for fully connecting all core subsystems of the OR1200, but without adding additional protocol semantics, state machines or data caches.

module or1200_top(
    // System
    input clk_i,
    input rst_i,
    input [ppic_ints-1:0] pic_ints_i,
    input [1:0] clmode_i,

    // Instruction WISHBONE INTERFACE
    //iwb_clk_i, iwb_rst_i,
    input iwb_ack_i,
    input iwb_err_i,
    input iwb_rty_i,
    input [31:0] iwb_dat_i,
    output iwb_cyc_o,
    output [31:0] iwb_adr_o,
    output iwb_stb_o,
    output iwb_we_o,
    output [3:0] iwb_sel_o,
    output [31:0] iwb_dat_o,
`ifdef OR1200_WB_CAB
    output iwb_cab_o,
`endif
`ifdef OR1200_WB_B3
    output [2:0] iwb_cti_o,
    output [1:0] iwb_bte_o,
`endif
    // Data WISHBONE INTERFACE
    //dwb_clk_i, dwb_rst_i,
    input dwb_ack_i,
    input dwb_err_i,
    input dwb_rty_i,
    input [31:0] dwb_dat_i,
    output dwb_cyc_o,
    output [31:0] dwb_adr_o,
    output dwb_stb_o,
    output dwb_we_o,
    output [3:0] dwb_sel_o,
    output [31:0] dwb_dat_o,
`ifdef OR1200_WB_CAB
    output dwb_cab_o,
`endif
`ifdef OR1200_WB_B3
    output [2:0] dwb_cti_o,
    output [1:0] dwb_bte_o,
`endif

    // External Debug Interface
    input dbg_stall_i,
    input dbg_ewt_i,
    output [3:0] dbg_lss_o,
    output [1:0] dbg_is_o,
    output [10:0] dbg_wp_o,
    output dbg_bp_o,
    input dbg_stb_i,
    input dbg_we_i,
    input [31:0] dbg_adr_i,
    input [31:0] dbg_dat_i,
    output [31:0] dbg_dat_o,
    output dbg_ack_o,

`ifdef OR1200_BIST
    // RAM BIST
    input mbist_si_i,
    output mbist_so_o,
    input [`OR1200_MBIST_CTRL_WIDTH - 1:0] mbist_ctrl_i,
`endif
    // Power Management
    input pm_cpustall_i,
    output [3:0] pm_clksd_o,
    output pm_dc_gate_o,
    output pm_ic_gate_o,
    output pm_dmmu_gate_o,
    output pm_immu_gate_o,
    output pm_tt_gate_o,
    output pm_cpu_gate_o,
    output pm_wakeup_o,
    output pm_lvolt_o
);
