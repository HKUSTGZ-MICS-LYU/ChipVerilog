1. Structural composition
The module instantiates and connects the following major blocks:
- or1200_iwb_biu / or1200_wb_biu for instruction and data WISHBONE adaptation.
- or1200_immu_top and or1200_dmmu_top for address translation and access control.
- or1200_ic_top and or1200_dc_top for instruction and data cache paths.
- or1200_cpu as the processor datapath and control pipeline.
- or1200_qmem_top for optional embedded memory interception.
- or1200_sb as the store buffer between data cache side and BIU side.
- or1200_du as the debug unit.
- or1200_pic, or1200_tt, and or1200_pm as architectural peripheral/control blocks.

2. High-level datapath behavior
2.1 Instruction path
- The CPU emits instruction fetch requests.
- The IMMU translates/protects instruction addresses.
- QMEM logic optionally intercepts accesses that target embedded instruction memory.
- Remaining traffic flows through the instruction cache and then through the instruction BIU to the external WISHBONE bus.
- Returned instruction data, acknowledge, retry, error, and tag information are propagated back toward the CPU.

2.2 Data path
- The CPU emits load/store traffic.
- The DMMU translates/protects data addresses.
- QMEM logic optionally intercepts accesses that target embedded data memory.
- Remaining traffic flows through the data cache.
- Stores may be decoupled through the store buffer before reaching the external data BIU.
- Returned read data and completion status are propagated back to the CPU.

2.3 Special-purpose register path
- The CPU’s SPR unit generates grouped chip-selects and a shared SPR address/data bus.
- Each sub-block that exposes architectural SPRs receives its group select and returns a read datapath value.
- The CPU-side SPR mux logic chooses the proper source based on the SPR group.

3. Control interactions
- Debug unit can stall execution, inject reads/writes to SPR space, observe exceptions, and drive breakpoint/watchpoint reporting.
- PIC asserts a CPU interrupt request and wakeup request.
- Tick timer asserts timer interrupt requests.
- PM block can gate clocks to the CPU, caches, MMUs, and timer.
- MBIST path serially chains through memory-related blocks.

4. Required functional guarantees
An implementation conforming to this spec shall:
- Expose one instruction WISHBONE master port and one data WISHBONE master port.
- Correctly arbitrate and route instruction/data traffic through MMU/cache/QMEM/BIU chains.
- Connect the CPU to the debug unit, PIC, TT, PM, and SPR infrastructure.
- Preserve precise completion/error signaling from memory hierarchy back to the CPU.
- Preserve top-level behavior when optional sub-features are compiled out by defines.
- Preserve zero or safe defaults for disabled optional features.

5. Notes specific to hyper pipelining
The PDF describes the hyper-pipelined core as keeping the original functionality while adding extra clocks and routing CMLS into memory structures. A regenerated implementation based on this spec should therefore treat this top module as the system wrapper that anchors memory, bus, and architectural side effects while allowing the internal core timing structure to be transformed.
