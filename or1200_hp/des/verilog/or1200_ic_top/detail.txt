This module is the complete instruction-cache top level. It integrates the instruction-cache FSM, data RAM, and tag RAM, and presents a unified interface between the CPU-side instruction request channel and the external instruction BIU.

1. Major responsibilities
- perform tag lookup and hit/miss detection;
- select between cache-hit data and external bus return data;
- control line refill through the FSM;
- allow software-driven invalidation through SPR writes;
- bypass the cache entirely when instruction cache is disabled.

2. Key internal components
The module instantiates:
- or1200_ic_fsm: control logic for hit/miss/refill;
- or1200_ic_ram: cache data storage;
- or1200_ic_tag: cache tag/valid storage.
It also contains local combinational logic for tag comparison and request/response muxing.

3. Important internal signals
- tag_v and tag: outputs of tag RAM.
- from_icram: fetched instruction word from data RAM.
- saved_addr: refill/write address from FSM.
- icram_we and ictag_we: write enables.
- ic_addr: selected address sent to BIU or used for tag/RAM indexing.
- tagcomp_miss: hit/miss result.
- ic_inv: invalidate request driven by SPR write.

4. Functional behavior
4.1 BIU-side outputs
The module drives the external instruction BIU signals. In cache-enabled mode:
- icbiu_cyc_o and icbiu_stb_o come from the FSM’s biu_read signal.
- icbiu_sel_o is 4'b1111 during cache refill reads.
- icbiu_cab_o follows the FSM’s burst signal.
In cache-disabled mode the CPU-side request is passed directly through to the BIU.
Writes are never generated by this module for normal fetches; icbiu_we_o = 0.

4.2 CPU-side completion
- icqmem_ack_o is a cache hit ack or first-miss ack when cache is enabled; otherwise it is the direct BIU ack.
- icqmem_err_o is the first-miss error when cache is enabled; otherwise the direct BIU error.
- icqmem_rty_o is defined as not-ack and not-err, giving a retry indication while waiting.
- icqmem_tag_o passes the instruction tag, replacing it with bus-error tag when icqmem_err_o is asserted.

4.3 Address selection
ic_addr selects between:
- saved_addr during cache refill/bus read sequences;
- current CPU request address for ordinary tag lookup/direct access.
This lets the same RAM/tag storage and BIU address path serve both normal fetch and refill traffic.

4.4 Tag write and invalidation
ictag_we is asserted either when the FSM wants to commit a newly refilled line or when software requests invalidation through SPR.
- ic_inv = spr_cs & spr_write
- ictag_addr selects the index from spr_dat_i during invalidation, otherwise from the active cache address.
- ictag_v is deasserted during invalidation so the written tag entry becomes invalid.
This creates a very simple invalidate-by-index mechanism.

4.5 Data path
- Data written into ic_ram during refill comes from icbiu_dat_i.
- On a cache hit, the instruction word returned to the CPU comes from from_icram.
- During bypass or cache-disabled mode, the external BIU data path is used instead.

4.6 Tag comparison
A conforming implementation must compare the requested address tag against the tag RAM output and treat the access as a hit only when tag_v is set and the tags match. The original source keeps the miss result in tagcomp_miss and feeds it into the FSM.

5. Disabled-cache mode
If the cache is disabled, this module must act as a pass-through wrapper between CPU-side request signals and BIU signals. This is necessary because the rest of the processor should still fetch instructions even when I$ is turned off.

6. Summary
or1200_ic_top.v is the full I$ subsystem boundary. It combines storage, control, refill sequencing, invalidate support, and cache bypass behavior into one CPU-visible instruction-cache block.
