Functional Overview:
Module `or1200_cpu` is the main OR1200 pipeline core that coordinates fetch, decode, execute, memory, write-back, and exception flow.

This module is the top-level CPU integration point for the OR1200 processor datapath and control path. It wires together the major blocks needed to execute instructions and connect the processor to:
- instruction-side bus / cache / IMMU
- data-side bus / cache / DMMU
- debug unit
- special-purpose register (SPR) space
- interrupt and tick exception sources

At project level, the PDF states that the “resulting hyper pipelined OR1200 core has the same inputs and outputs plus the new clk_i_cml_* clocks.” This module is therefore the natural reference for the architectural CPU interface that must be preserved.

Description:
This module is the top-level integrated module of the data path and control path of the OR1200 processor core. It is responsible for connecting sub-modules such as fetching, decoding, register file, operand selection, ALU, MAC/multiplier, LSU, exception handling, PC generation, debugging unit and SPR access into a complete CPU. The module provides external command-side and data-side bus interfaces, initiates requests to the instruction subsystem and data access subsystem respectively, and receives returned data, handshake and error information; it also exports debugging, MMU/cache enable, supervisory state and SPR interface signals.

The top layer itself hardly saves independent timing status. Timing updates mainly occur inside lower-level sub-modules and are uniformly driven by the rising edge of clk and reset by rst. The top-level responsibility is to connect these state machines and pipeline registers, and export key status register bits as function enable: dc_en, ic_en, dmmu_en, immu_en, supv and except_prefix respectively come from the data cache, instruction cache, data MMU, instruction MMU, supervision state and exception vector prefix related bits in the system status register SR, so these outputs are combined to reflect the current SR content. The debug exception stop vector du_except comes directly from the exceptions module's except_stop. The register file write enable we is determined by the write-back control rfwb_op[0]; the SPR chip select and write enable are generated uniformly by the SPRS/control path.

From a functional point of view, the control module first decodes the fetched instructions and generates control signals such as register read address, immediate data, branch offset, memory access offset, ALU/MAC/LSU opcode, writeback selection, SPR address immediate data, multi-cycle information, system calls, traps, illegal instructions, etc. The source operands output by the register file then go through operand selection and forward logic to generate the final execution operands sent to the ALU and LSU. ALU completes arithmetic logic, comparison, shift and customized instructions; MAC/multiplier completes multiplication and multiplication-accumulation operations; LSU initiates data access based on memory access type, address and write data. The writeback demultiplexer selects rf_dataw between ALU results, LSU return data, SPR read results, and link addresses based on rfwb_op and writes it back to the register file while providing the forward results to the previous stage.

In terms of control flow, genpc generates the next instruction fetch address based on branch type, flag bit, abnormal start, abnormal return EPC and software write PC request; the if unit receives instructions from the instruction bus and caches instructions that have been returned but not yet consumed when the pipeline freezes; the except module uniformly collects instruction fetch, memory access, illegal instructions, alignment, TLB/MMU, system calls, traps, interrupts and ticks and other exception sources, generates except_type, except_start, flushpipe and extended flush control, and maintains them. Exception-related registers such as EPC, EEAR, and ESR. The freezing logic combines conditions such as IF/LSU stall, multi-cycle execution, debug shutdown, abnormal flushing, and MAC busy to control whether the pipeline at all levels maintains the current state. The debug unit interacts with the CPU's internal registers and SPR space through du_stall, du_read/du_write and du_addr/du_dat_cpu, and can trigger hardware breakpoints or abnormal stops.

Therefore, the overall semantics of this module are: after the reset is released, the sub-module's internal state machine and pipeline registers jointly drive the CPU's normal instruction fetching, decoding, execution, memory access and write-back; when debugging shutdown, bus waiting, multi-cycle operation or exception occurs, the corresponding sub-module preempts the normal execution path through the freezing or flushing mechanism. The top level does not change these priorities, it is only responsible for connecting them correctly according to the implementation of OR1200.

Module name:
module or1200_cpu(
    // Clk & Rst
    input clk,
    input rst,

    // Insn interface
    output ic_en,
    output [31:0] icpu_adr_o,
    output icpu_cycstb_o,
    output [3:0] icpu_sel_o,
    output [3:0] icpu_tag_o,
    input [31:0] icpu_dat_i,
    input icpu_ack_i,
    input icpu_rty_i,
    input icpu_err_i,
    input [31:0] icpu_adr_i,
    input [3:0] icpu_tag_i,
    output immu_en,

    // Debug unit
    output [31:0] ex_insn,
    output ex_freeze,
    output [31:0] id_pc,
    output [2:0] branch_op,
    output [31:0] spr_dat_npc,
    output [31:0] rf_dataw,
    input du_stall,
    input [31:0] du_addr,
    input [31:0] du_dat_du,
    input du_read,
    input du_write,
    input [13:0] du_dsr,
    input du_hwbkpt,
    output [12:0] du_except,
    output [31:0] du_dat_cpu,

    // Data interface
    output dc_en,
    output [31:0] dcpu_adr_o,
    output dcpu_cycstb_o,
    output dcpu_we_o,
    output [3:0] dcpu_sel_o,
    output [3:0] dcpu_tag_o,
    output [31:0] dcpu_dat_o,
    input [31:0] dcpu_dat_i,
    input dcpu_ack_i,
    input dcpu_rty_i,
    input dcpu_err_i,
    input [3:0] dcpu_tag_i,
    output dmmu_en,

    // Interrupt & tick exceptions
    input sig_int,
    input sig_tick,

    // SPR interface
    output supv,
    output [31:0] spr_addr,
    output [31:0] spr_dat_cpu,
    input [31:0] spr_dat_pic,
    input [31:0] spr_dat_tt,
    input [31:0] spr_dat_pm,
    input [31:0] spr_dat_dmmu,
    input [31:0] spr_dat_immu,
    input [31:0] spr_dat_du,
    output [31:0] spr_cs,
    output spr_we
);
