
Module `or1200_reg2mem` aligns register write data into memory byte-lane format for store operations.

This module aligns register data to memory byte lanes for store operations. The source file describes it as “Aligns register data to memory alignment.” It transforms the 32-bit register operand into a 32-bit memory write-data word whose byte positions match the addressed store size and address offset.

Description:

The module aligns register write data into memory byte-lane format for store operations.


This module implements the alignment conversion of register write data to memory bus write data. Input `regdata` is 32-bit write data arranged according to logical values ​​within the processor, `addr[1:0]` represents the offset of the target storage address within the word, and `lsu_op` represents the current store type. The module outputs `memdata`, whose four bytes have been rearranged according to the bus byte lane position, and can directly drive the external data storage interface together with the `dcpu_sel_o` generated by the LSU.

The module is completely combinational logic, has no clock and reset, and does not save any state. The output `memdata` is concatenated by four independent byte register variables `memdata_hh`, `memdata_hl`, `memdata_lh`, `memdata_ll`, corresponding to `[31:24]`, `[23:16]`, `[15:8]` and `[7:0]` of the bus respectively. These bytes are updated immediately when `lsu_op`, `addr` or `regdata` changes.

The specific conversion rules reflect the big-endian lane alignment semantics. For the highest byte `memdata[31:24]`: if it is byte storage and the offset is `00`, take `regdata[7:0]`; if it is half-word storage and the offset is `00`, take `regdata[15:8]`; in other cases, the default is `regdata[31:24]`. For `memdata[23:16]`: `regdata[23:16]` is taken only when the aligned word storage `SW, addr=00` is taken, and `regdata[7:0]` is taken in other cases. For `memdata[15:8]`: If it is byte storage and the offset is `10`, then `regdata[7:0]` is taken, otherwise the default is `regdata[15:8]`. The lowest byte `memdata[7:0]` is always taken as `regdata[7:0]`.

These rules do not complete the memory access validity check alone, but assume that the upstream LSU has generated the correct byte enable `sel` based on `lsu_op` and the address. Therefore, for operations that only write one byte or half word, the module allows other unselected byte lanes to retain the default content from `regdata`, but these bytes will not actually be written to the memory because the corresponding lane will be masked by `sel`. The key responsibility of the module is to ensure that "the selected lane carries the correct low byte/low half word content" to form a match with the LSU's byte select.

module or1200_reg2mem(
    input [1:0] addr,
    input [3:0] lsu_op,
    input [31:0] regdata,
    output [31:0] memdata
);

Input ports:
    - addr[1:0]: Array index/address input.
    - lsu_op[3:0]: Encoded load/store operation selector.
    - regdata[31:0]: Register-side aligned data word.
Output port:
    - memdata[31:0]: Memory-side data word before alignment or extension.
Internal reg/wire signals:
    reg [7:0] memdata_hh: Signal that carries intermediate datapath values between logic stages.
    reg [7:0] memdata_hl: Signal that carries intermediate datapath values between logic stages.
    reg [7:0] memdata_lh: Signal that carries intermediate datapath values between logic stages.
    reg [7:0] memdata_ll: Signal that carries intermediate datapath values between logic stages.
