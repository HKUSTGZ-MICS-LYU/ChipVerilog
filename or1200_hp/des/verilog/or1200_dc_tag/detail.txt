1. Functional Requirements
1.1 Stored format
The tag RAM shall store a packed word whose LSB is the valid bit and whose upper bits are the cache tag.
The RTL outputs:
- tag_v = datout[0]
- tag = datout[dw-1:1] (logical interpretation)

1.2 Access behavior
When enabled, the RAM shall return the tag entry indexed by addr.
When we is asserted, it shall write the packed tag/valid input.

1.3 Use cases
The top-level cache uses this RAM for:
- line allocation / refill completion
- cache invalidation through SPR writes
- hit/miss determination by comparing stored tag with request address tag and checking tag_v

2. No-Cache Configuration
The RTL contains OR1200_NO_DC handling. In a no-data-cache build, the module behavior may degrade to a stub or simplified implementation, but the cache top-level architectural contract remains valid.

3. Physical Implementation Variants
Like the data RAM, this block may be realized with implementation-specific SRAM macros. A compatible reimplementation may choose different primitives provided the functional contract is preserved.

4. BIST Support
When OR1200_BIST is enabled, the module shall participate in the MBIST chain.

5. Implementation Constraints
A compatible implementation shall:
- preserve packed tag+valid storage format
- preserve single-bit write-enable semantics
- preserve the width implied by OR1200_DCTAG_W and OR1200_DCTAG
- interoperate with or1200_dc_top hit/miss logic exactly
