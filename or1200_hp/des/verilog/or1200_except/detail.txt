1. Exception Classes Covered
The RTL recognizes at least:
- tick timer
- interrupt
- instruction MMU fault
- instruction TLB miss
- instruction bus error
- illegal instruction
- alignment error
- data TLB miss
- data MMU fault
- data bus error
- range exception
- trap
- system call

2. Priority Rules
The RTL explicitly forms except_trig as a priority-ordered vector. A compatible implementation shall preserve the architectural priority order defined there.
Important properties:
- events can be masked/redirected by debug status register du_dsr
- trap and syscall are suppressed while ex_freeze is active
- interrupt/tick are additionally gated by SR enable bits and delay logic

3. Pipeline-State Tracking
The module shall maintain pipeline PCs and selected exception flags across stages:
- id_pc follows if_pc when decode is not frozen
- ex_pc follows id_pc when execute is not frozen
- wb_pc follows ex_pc when write-back is not frozen
- exception flags for instruction-side faults are pipelined along with the PCs
This allows the exception logic to report the correct architecturally associated PC.

4. Delayed enable behavior
The RTL uses delayed_iee and delayed_tee shift registers so that restoring SR[IEE] or SR[TEE] with l.rfe does not immediately re-enable interrupt/tick exceptions in the same vulnerable cycle.
A compatible implementation shall preserve this delayed-enable semantics.

5. Core Output Semantics
5.1 except_start
except_start shall assert when except_type is not NONE and extend_flush is active.

5.2 except_started
except_started = extend_flush & except_start.
This indicates the handler startup window.

5.3 flushpipe
flushpipe shall assert when:
- an exception-triggered flush is requested
- pc_we is asserted
- extend_flush is active

5.4 except_flushpipe
The RTL defines except_flushpipe when any exception trigger is present and the FSM is idle. This begins handler sequencing.

5.5 abort_ex
abort_ex shall assert for data-side faults that invalidate execution/write-back of a load or related instruction:
- dbuserr
- dmmufault
- dtlbmiss
- align
- illegal

5.6 PPC/NPC outputs
- spr_dat_ppc returns wb_pc
- spr_dat_npc returns ex_pc, or id_pc when ex_void is asserted
- lr_sav = ex_pc[31:2]

6. Saved State Requirements
The module shall manage the exception save registers:
- EPCR: exception PC register
- EEAR: exception effective address register
- ESR: exception status register
These registers can also be updated by explicit SPR writes via epcr_we/eear_we/esr_we, so a compatible implementation must preserve both exception-driven and software-driven update paths.

7. Exception FSM
The module contains a dedicated FSM controlling exception sequencing.
At minimum, the FSM shall:
- detect a new exception when idle
- choose except_type according to priority
- hold extend_flush for the startup window of the handler
- capture EPCR/EEAR/ESR at the correct point
- return to idle after the handler fetch sequence is established

8. Debug-Unit Interaction
The vector except_stop reports exception events that are configured to stop in the debug unit rather than directly triggering normal exception flow.
The CPU top-level forwards this vector to the debug interface as du_except.
A compatible implementation shall preserve the exact bit ordering and gating semantics.

9. Implementation Constraints
A compatible implementation shall preserve:
- exception recognition set
- priority order
- delayed interrupt/tick re-enable behavior
- flush/start/started semantics
- PPC/NPC/EPCR/EEAR/ESR behavior
- interaction with pipeline freeze signals
- debug stop gating through du_dsr
