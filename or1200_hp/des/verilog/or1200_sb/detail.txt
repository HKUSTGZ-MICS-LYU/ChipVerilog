1. FIFO payload
Each buffered store entry contains:
- byte select,
- write data,
- address.
The FIFO stores only write transactions, not reads.

2. Buffering policy
- fifo_wr is asserted as dcsb_cyc_i & dcsb_stb_i & dcsb_we_i & ~fifo_full & ~fifo_wr_ack
- The FIFO write is acknowledged upstream by fifo_wr_ack on the next clock.
- fifo_rd is asserted as ~outstanding_store, causing the next queued entry to be presented when the current buffered store has completed.

3. Upstream/downstream multiplexing
- If the store buffer is selected (sel_sb), the downstream BIU sees the queued store entry and control generated by the store buffer.
- Otherwise, downstream signals are direct pass-through from the upstream side.
- Reads and non-buffered operations therefore continue to pass transparently.

4. Completion behavior
- outstanding_store tracks whether a buffered store is currently active toward the BIU.
- When the BIU acknowledges the store, outstanding_store clears.
- While outstanding_store is set or the FIFO is non-empty, sel_sb remains asserted while either the FIFO is non-empty or a store is outstanding and the buffer continues to drive the downstream interface.
- outstanding_store is set when sel_sb | fifo_wr and cleared when sbbiu_ack_i.

5. Error behavior
- Buffered stores never report an upstream error directly; dcsb_err_o is forced low when sel_sb is active.
- When the buffer is bypassed, upstream error directly reflects sbbiu_err_i.

6. Disabled-feature behavior
If the store buffer is not implemented, the module is a pure pass-through between dcsb_* and sbbiu_*.

7. Required functional guarantees
An implementation conforming to this spec shall:
- Buffer write transactions in FIFO order.
- Allow writes to be acknowledged upstream before final downstream completion.
- Preserve read and bypass transactions transparently.
- Track one outstanding buffered store toward the BIU at a time.
- Continue driving queued stores until each one is acknowledged downstream.
