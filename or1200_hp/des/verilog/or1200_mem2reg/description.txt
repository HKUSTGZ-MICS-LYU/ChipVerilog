
Module `or1200_mem2reg` aligns and sign/zero-extends loaded memory bytes/halves/words into register write-back format.

This module converts a 32-bit memory-return word into the 32-bit value that must be written back to the register file for OR1200 load instructions. The source comments note that it contains different implementations of memory-to-register alignment.

Description:

The module aligns and sign/zero-extends loaded memory bytes/halves/words into register write-back format.


This module implements alignment and expansion conversion from reading data from the memory to writing data back to the register. Input `memdata` is 32-bit data arranged according to bus byte lane, `addr[1:0]` represents the byte offset of the target access in the word, `lsu_op` represents the load type. Based on this information, the module outputs `regdata` that has been byte aligned, half-word aligned, zero-extended or sign-extended for the pipeline to write back to the register file.

The module is entirely combinational logic, without any registers, and has no clock or reset behavior; the outputs are updated immediately when `addr`, `lsu_op` or `memdata` changes. There are two sets of optional structures in implementation: if `OR1200_IMPL_MEM2REG2` is defined, use more fine-grained four-byte selection and expansion control; otherwise, use the direct implementation of "first align left by address, then expand by load type". The final semantics of both implementations are consistent.

In the default direct implementation, the first step is to generate the intermediate value `aligned` based on `addr`: when the offset is `00`, the original data remains unchanged; when the offset is `01`/`10`/`11`, the required bytes or halfwords are moved to the high position respectively, that is, `{memdata[23:0],8'b0}`, `{memdata[15:0],16'b0}` or `{memdata[7:0],24'b0}`. The second step selects the output format according to `lsu_op`: `LBZ` takes `aligned[31:24]` as the lowest byte and clears the high 24 bits; `LBS` also takes the byte, but copies all the high 24 bits of its sign bit; `LHZ` takes `aligned[31:16]` as the low 16 bits and clears the high 16 bits; `LHS` takes the same 16 bits, but sign-extends the upper 16 bits; in other cases (such as `LWZ/LWS`), `aligned` is output directly, that is, it is returned unchanged after word alignment is completed.

In an implementation with `OR1200_IMPL_MEM2REG2` enabled, the above semantics are split into four independent byte selectors: each output byte determines whether to take a certain byte of the input, all zeros, or copy the sign bit of an input byte. In this way, in the `LB*` and `LH*` scenarios, the higher bytes will be filled according to the zero extension or sign extension rules; in the word access scenario, the four output bytes together form the aligned whole word. Regardless of the implementation, the module does not detect misalignment errors on its own and assumes by default that the upstream LSU has guaranteed that only legal `lsu_op/addr` combinations will enter here.

module or1200_mem2reg(
    input [1:0] addr,
    input [3:0] lsu_op,
    input [31:0] memdata,
    output [31:0] regdata
);

Input ports:
    - addr[1:0]: Array index/address input.
    - lsu_op[3:0]: Encoded load/store operation selector.
    - memdata[31:0]: Memory-side data word before alignment or extension.
Output port:
    - regdata[31:0]: Register-side aligned data word.
Internal reg/wire signals:
    reg [7:0] regdata_hh: Register-data [31:24] byte.
    reg [7:0] regdata_hl: Register-data [23:16] byte.
    reg [7:0] regdata_lh: Register-data [15:8] byte.
    reg [7:0] regdata_ll: Register-data [7:0] byte.
    reg [31:0] aligned: Aligned load-data word before byte extraction.
    reg [3:0] sel_byte0: Byte-selector control for output lane 0.
    reg [3:0] sel_byte1: Byte-selector control for output lane 1.
    reg [3:0] sel_byte2: Byte-selector control for output lane 2.
    reg [3:0] sel_byte3: Byte-selector control for output lane 3.
    reg [31:0] regdata: Register data.
    reg [31:0] aligned: Aligned load-data word before byte extraction.
