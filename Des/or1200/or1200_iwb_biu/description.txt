or1200_iwb_biu is the OR1200 processor’s instruction-side Wishbone bus interface unit. This module converts OR1200 internal BIU-style instruction-fetch requests into external Wishbone master bus transactions, and converts the read data, normal completion response, and error response returned by the external Wishbone bus back to the internal BIU interface. It is not merely a signal-renaming bridge; it also includes Wishbone cycle/strobe generation, read-data return, ack/err response conversion, response phase control under fixed clock-ratio modes, repeated-access fast acknowledgment, optional retry handling, graceful-abort handling, and optional CAB and Wishbone B3 burst support.

The module contains logic in both the RISC clock domain and the Wishbone clock domain. clk/rst are used for RISC-side logic, mainly including valid_div and repeated_access_ack. wb_clk_i/wb_rst_i are used for Wishbone-side registered logic, including registered Wishbone outputs, the registered input return path, previous_complete, aborted_r, the retry counter, and the optional burst counter. Therefore, clk should not be understood as the only clock that updates all sequential state in the module; most Wishbone-related state is driven by wb_clk_i.

clmode[1:0] describes the fixed frequency relationship between the Wishbone clock and the RISC clock. In the code, 2'b00 means Wishbone and RISC run at the same frequency, 2'b01 means Wishbone runs at half the RISC frequency, 2'b10 is unused or N/A, and 2'b11 means Wishbone runs at one quarter of the RISC frequency. The phase qualification of biu_ack_o and biu_err_o through clmode is not unconditional; it is controlled by macros such as OR1200_CLKDIV_2_SUPPORTED and OR1200_CLKDIV_4_SUPPORTED. valid_div is a 2-bit counter in the RISC clock domain. It is used to make the internal BIU observe completion or error responses only on the appropriate RISC cycles when Wishbone runs slower than RISC. This logic is response phase control for OR1200’s fixed clock-ratio modes, not a general-purpose asynchronous CDC synchronizer.

On the Wishbone output path, the module has two types of behavior depending on whether OR1200_REGISTERED_OUTPUTS is enabled. When this macro is enabled, outputs such as wb_adr_o, wb_cyc_o, wb_stb_o, wb_we_o, wb_sel_o, wb_dat_o, and the optional wb_cab_o and wb_cti_o are registered on wb_clk_i and reset by wb_rst_i. In this mode, a normal internal request can start a Wishbone cycle; an active retry suppresses new normal requests; a repeated_access hit prevents a new external Wishbone transaction from being issued; and if a graceful abort occurs, the already-issued external transaction is kept active until the Wishbone side returns ack or err.

When OR1200_REGISTERED_OUTPUTS is not enabled, several Wishbone outputs are combinational. For example, wb_adr_o directly equals biu_adr_i, wb_dat_o directly equals biu_dat_i, wb_sel_o directly equals biu_sel_i, wb_we_o equals biu_cyc_i & biu_stb_i & biu_we_i, and wb_stb_o equals biu_cyc_i & biu_stb_i. It is important to note that, in non-registered-output mode, wb_stb_o is not masked by retry, repeated-access, or abort logic. Therefore, the wb_stb_o behavior in registered-output mode must not be generalized to all configurations. In non-registered-output mode, wb_cyc_o is also generated by combinational logic, and whether it is affected by retry depends on macros such as OR1200_NO_BURSTS and on the exact expression used.

On the input data return path, the module is also controlled by OR1200_REGISTERED_INPUTS. When this macro is enabled, biu_dat_o, long_ack_o, and long_err_o are registered signals generated in the wb_clk_i domain. biu_dat_o captures wb_dat_i when wb_ack_i is asserted, long_ack_o captures wb_ack_i & ~aborted, and long_err_o captures wb_err_i & ~aborted. When this macro is not enabled, long_ack_o directly equals wb_ack_i, long_err_o equals wb_err_i & ~aborted_r, and biu_dat_o is generated combinationally: it selects the saved previous read data wb_dat_r when repeated_access_ack is asserted, otherwise it selects the current wb_dat_i.

biu_ack_o is the normal completion response returned to the internal BIU. It is triggered by either repeated_access_ack or long_ack_o, and is masked by ~aborted_r. When clock-divider support macros are enabled, it is further phase-qualified by valid_div and clmode. Therefore, biu_ack_o should be understood as the RISC-side visible completion response, not as a simple copy of the external Wishbone wb_ack_i. biu_err_o is generated from long_err_o and is subject to similar valid_div/clmode phase qualification, but it does not include the repeated_access_ack path.

The module implements a repeated-access fast acknowledgment mechanism. The code saves the wb_dat_i value returned on the previous Wishbone ack into wb_dat_r, compares wb_adr_o with the current biu_adr_i to generate same_addr, and combines this with previous_complete to generate repeated_access. When repeated_access & biu_cyc_i & biu_stb_i is detected in the RISC clock domain, repeated_access_ack is asserted for one RISC clock cycle to complete the internal request quickly. In registered-output mode, repeated_access prevents new external wb_cyc_o and wb_stb_o assertions. One important detail is that the repeated-access condition in the code does not explicitly check biu_we_i. Therefore, at the hardware-condition level, it is not explicitly restricted to read requests by biu_we_i == 0. Since this module is the instruction-side BIU, the practical use case is usually instruction-fetch reads, so the mechanism normally behaves as a repeated-read optimization; however, the description should not state that a read qualifier is explicitly implemented in the code.

previous_complete is a Wishbone-clock-domain state bit used by repeated-access detection and by some CAB/burst address-update conditions. When wb_rst_i is asserted, previous_complete is set to 1'b1. It is also set to 1'b1 when wb_ack_i & biu_cyc_i & biu_stb_i is true. It is cleared when a new internal request starts, there is no current wb_ack_i, no abort condition, and no still-pending wb_stb_o. Neither wb_err_i nor wb_rty_i sets previous_complete; only a qualifying wb_ack_i indicates that the previous access completed normally.

Retry handling exists only when OR1200_WB_RETRY is enabled. When wb_rty_i is sampled, the module loads retry_cntr; as long as this counter is nonzero, retry remains asserted. retry is not returned to the internal BIU as a separate output, and it does not generate biu_ack_o. Instead, it is used internally to pause or suppress new normal Wishbone requests. In registered-output mode, retry masks the assertion of normal wb_cyc_o and wb_stb_o. In non-registered-output mode, however, wb_stb_o is not masked by retry, and whether wb_cyc_o is affected by retry depends on the exact macro configuration and combinational expression. Therefore, the effect of retry must be understood together with OR1200_WB_RETRY, OR1200_REGISTERED_OUTPUTS, and the burst-related macros.

The graceful-abort logic handles the case where an external Wishbone transaction has already been issued, the internal biu_cyc_i & biu_stb_i request is withdrawn early, and the current Wishbone cycle has not yet received wb_ack_i or wb_err_i. The combinational signal aborted is asserted when wb_stb_o is already active, the internal request has been withdrawn, and there is no external termination response in the current cycle. aborted_r records this state in the Wishbone clock domain and remains asserted until the external Wishbone bus returns wb_ack_i or wb_err_i. In registered-output mode, this logic keeps external wb_cyc_o and wb_stb_o asserted so that the already-issued Wishbone transaction can be formally terminated by the external bus rather than being left hanging after the internal request is canceled. biu_ack_o masks normal completion responses through ~aborted_r, and the error response path is also masked by either aborted or aborted_r depending on whether the registered-input or non-registered-input configuration is used.

When OR1200_WB_CAB is enabled, the module provides the wb_cab_o output to forward consecutive-address burst requests. In registered-output mode, wb_cab_o captures biu_cab_i on wb_clk_i; in non-registered-output mode, wb_cab_o directly equals biu_cab_i. CAB also affects some wb_cyc_o hold behavior and address-update logic, depending on whether burst-related macros are enabled.

When OR1200_WB_B3 is enabled, the module provides the Wishbone B3 signals wb_cti_o, wb_bte_o, and the internal burst_len counter. burst_len is counted in the wb_clk_i domain and tracks the remaining beats in a 4-beat burst. In registered-output mode, wb_cti_o outputs classic cycle, incrementing burst cycle, or end-of-burst according to biu_cab_i, burst_len, and wb_ack_i. wb_bte_o is fixed to 2'b01, indicating a 4-beat wrap burst. It is important to note that when OR1200_WB_B3 is enabled but OR1200_REGISTERED_OUTPUTS is not enabled, the code does not implement wb_cti_o; instead, it marks that case as unsupported. Therefore, B3 support should be understood as depending on the registered-output configuration.

The module has two reset domains. rst resets the RISC-clock-domain registers valid_div and repeated_access_ack. wb_rst_i resets Wishbone-clock-domain state, including registered Wishbone outputs, registered input signals, wb_dat_r, previous_complete, aborted_r, the retry counter, and the optional burst counter. Notably, previous_complete is set to 1'b1 after wb_rst_i, rather than being cleared.

In summary, or1200_iwb_biu is a macro-configurable OR1200 instruction-side BIU-to-Wishbone master protocol conversion module. It accepts internal biu_* requests, generates external wb_* Wishbone transactions, and converts external bus read data, normal completion, and error termination back into biu_dat_o, biu_ack_o, and biu_err_o. An accurate description of this module must distinguish registered and non-registered input/output configurations, account for the different effects of retry, abort, and repeated-access under different macro settings, and recognize that clmode/valid_div provide response phase control for fixed clock-ratio modes rather than a general-purpose clock-domain crossing mechanism.

Processing Flow

The processing flow starts when the internal BIU presents a request through biu_cyc_i, biu_stb_i, biu_adr_i, biu_we_i, biu_sel_i, biu_dat_i, and optionally biu_cab_i. The module first determines whether the request should be issued as a new external Wishbone transaction or handled by an internal fast path. In particular, it checks whether the current address matches the previously completed access and whether previous_complete is set. If this repeated-access condition is met, the module can assert repeated_access_ack and complete the internal request without issuing a new Wishbone transaction, subject to the active macro configuration and input/output registration mode.

If the request is not completed through the repeated-access path, the module drives the Wishbone request signals. In registered-output mode, the Wishbone address, data, select, write-enable, cycle, strobe, and optional burst-related outputs are updated on wb_clk_i. In this mode, normal request launch is blocked by retry and repeated-access conditions, and an already-issued transaction may be extended by the abort logic until the external bus returns a terminating response. In non-registered-output mode, several Wishbone outputs are directly derived from the BIU inputs, so retry, repeated-access, and abort do not affect all output signals in the same way as in registered-output mode.

During the external Wishbone transaction, the module monitors wb_ack_i, wb_err_i, and optionally wb_rty_i. A normal wb_ack_i indicates successful completion and may update wb_dat_r, biu_dat_o, long_ack_o, and previous_complete, depending on the registered-input configuration and current state. A wb_err_i produces the internal error path through long_err_o and then biu_err_o, with abort-related masking applied according to the input registration mode. If OR1200_WB_RETRY is enabled and wb_rty_i is sampled, the retry counter is loaded and retry remains active until the counter expires, temporarily suppressing new normal Wishbone requests in configurations where retry masking is implemented.

If the internal BIU withdraws biu_cyc_i & biu_stb_i after an external Wishbone strobe has already been issued but before wb_ack_i or wb_err_i is received, the graceful-abort logic asserts aborted and records it in aborted_r. This keeps the external Wishbone transaction alive in registered-output mode until the external bus formally terminates it with ack or err, while preventing a canceled internal request from being treated as a normal completed request.

Finally, the module converts the Wishbone-side completion or error indication into the internal BIU response. biu_ack_o is generated from long_ack_o or repeated_access_ack, masked by ~aborted_r, and optionally phase-qualified by valid_div and clmode when clock-divider support macros are enabled. biu_err_o is generated from long_err_o and is subject to the same kind of valid_div/clmode phase qualification, but it does not include the repeated-access path. The read data returned on biu_dat_o comes either from the registered Wishbone input data, the current wb_dat_i, or the saved previous data wb_dat_r, depending on whether registered inputs are enabled and whether repeated-access acknowledgment is active.
