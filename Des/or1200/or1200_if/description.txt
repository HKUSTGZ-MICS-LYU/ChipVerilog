or1200_if is the instruction-fetch return handling and IF-stage buffering module in the OR1200 processor. It sits between the instruction-side memory/cache return interface and the following pipeline stages. It receives returned instruction data, address, acknowledge, error, and tag information from the instruction-side interface, and converts these signals into the IF-stage instruction, PC, stall, refetch, and instruction-fetch exception signals used by the rest of the pipeline. It should be noted that this module does not initiate instruction-fetch requests and does not generate new instruction-fetch address request signals; it only processes results that have already been returned by the instruction-side interface.

The module contains a one-entry save mechanism consisting of three registers: saved, insn_saved, and addr_saved. This mechanism handles the case where the instruction-side interface returns a fetch result while the pipeline is frozen. When if_freeze is 1, icpu_ack_i is 1, and no instruction has already been saved, meaning saved is 0, the module captures the currently returned instruction icpu_dat_i into insn_saved on the rising clock edge. At the same time, it saves the corresponding address icpu_adr_i into addr_saved and sets saved to 1. This prevents an already returned fetch result from being lost while the IF stage is frozen.

The output if_insn is determined by combinational logic with a clear priority order. The highest priority is error or control-related NOP insertion: when any of icpu_err_i, no_more_dslot, or rfe is 1, if_insn is forced to the special NOP instruction {OR1200_OR32_NOP, 26'h041_0000}. If none of these conditions is true and savedis 1, the saved instructioninsn_savedis output. If there is no saved instruction buticpu_ack_iis 1 in the current cycle, the currently returned instructionicpu_dat_iis output. If there is neither a saved instruction nor a new valid fetch return, the default NOP instruction{OR1200_OR32_NOP, 26'h061_0000} is output. Therefore, the module does not present undefined data to the next stage when no valid fetch result is available.

It is important to note that if_freeze does not directly participate in the combinational selection of if_insn. In other words, in a cycle where saved is 0 and icpu_ack_i is 1, as long as icpu_err_i, no_more_dslot, and rfe do not take priority, if_insn will combinationally output the current icpu_dat_i, regardless of whether if_freeze is 1. The role of if_freeze is mainly in the sequential logic: it determines whether the currently returned instruction and address should be saved into the internal registers when a fetch acknowledge is received, so that they can be used after the freeze is released.

The output logic for if_pc is relatively simple. When saved is 1, if_pc outputs the saved address addr_saved; otherwise, it outputs the current interface address icpu_adr_i. This keeps the saved instruction and its corresponding PC together when a buffered instruction is replayed. However, because error or control-related NOP insertion in if_insn has higher priority than saved, when icpu_err_i, no_more_dslot, or rfe is asserted, if_insn may be replaced by the special NOP even though if_pc still comes from addr_saved.

if_stall indicates whether the IF stage is still waiting for an available fetch result. In the current implementation, if_stall is asserted when there is no error return, no normal acknowledge return, and no saved instruction, that is, under the condition !icpu_err_i & !icpu_ack_i & !saved. Therefore, as long as the instruction-side interface has not yet returned a valid result and the module does not have a buffered instruction available for the next stage, the IF stage is considered to be stalled. In the current version, if_stall is no longer controlled by no_more_dslot; the old implementation, which is left commented out in the code, previously included the !no_more_dslot condition.

genpc_refetch is asserted when saved and icpu_ack_i are both 1. This means that the module already holds a saved instruction that has not yet been normally delivered, while the instruction-side interface has returned another acknowledge. This signal informs the PC generation logic that, because the IF buffer is already occupied, the newly returned fetch result may need to be refetched or handled again.

The instruction-fetch exception signals are generated by combinationally decoding icpu_err_i and icpu_tag_i. When icpu_err_i is 1 and icpu_tag_i equals OR1200_ITAG_TE, except_itlbmiss is asserted, indicating an instruction TLB miss. When icpu_tag_i equals OR1200_ITAG_PE, except_immufault is asserted, indicating an instruction MMU page or permission fault. When icpu_tag_i equals OR1200_ITAG_BE, except_ibuserr is asserted, indicating an instruction bus error. All three exception signals are suppressed by no_more_dslot; that is, when no_more_dslot is 1, no exception is reported even if there is a fetch error and the tag matches. Apart from this, these exception outputs are not directly suppressed by saved, if_freeze, flushpipe, or rfe.

The three internal state registers are all updated in always blocks sensitive to posedge clk or posedge rst, so rst is an active-high asynchronous reset signal. On reset, saved is cleared, insn_saved is set to the special NOP {OR1200_OR32_NOP, 26'h041_0000}, and addr_savedis cleared to32'h00000000. When flushpipe` is asserted, these three registers are also cleared to values similar to their reset states, discarding any currently saved fetch result.

When neither reset nor pipeline flush is active, the update rule for saved is as follows: if icpu_ack_i and if_freeze are both 1 and the current saved value is 0, saved is set to 1; if the freeze is released, that is, if_freeze is 0, saved is cleared; otherwise, it retains its previous value. The update rule for insn_saved corresponds to the save condition: it captures icpu_dat_i when a new acknowledge is received during freeze and no instruction has already been saved; it returns to the special NOP when if_freeze is 0; otherwise, it retains its previous value. addr_saved captures icpu_adr_i when a new acknowledge is received during freeze and no address has already been saved; when if_freeze is 0, it is updated to the current icpu_adr_i, meaning it tracks the current interface address in the non-frozen state; otherwise, it retains its previous value.

In summary, the main role of or1200_if is to organize the fetch results returned by the instruction-side interface into an instruction and PC usable by the IF stage, while providing a one-entry instruction/address save capability during pipeline freezes to prevent already returned fetch results from being lost. At the same time, it inserts a default NOP when no valid return is available, inserts a special NOP on fetch error, delay-slot suppression, or return-from-exception control, and generates the corresponding instruction-fetch exception signals according to the fetch error tag.

module or1200_if(
    // Clock and reset
    input clk,
    input rst,

    // External i/f to IC
    input [31:0] icpu_dat_i,
    input icpu_ack_i,
    input icpu_err_i,
    input [31:0] icpu_adr_i,
    input [3:0] icpu_tag_i,

    // Internal i/f
    input if_freeze,
    output [31:0] if_insn,
    output [31:0] if_pc,
    input flushpipe,
    output if_stall,
    input no_more_dslot,
    output genpc_refetch,
    input rfe,
    output except_itlbmiss,
    output except_immufault,
    output except_ibuserr
);

Input ports:
    - clk: Primary clock; sequential state in this module updates on its rising edge.
    - rst: Reset input that returns local state elements to their defined reset values.
    - icpu_dat_i[31:0]: Data bus for the CPU-to-instruction-memory interface.
    - icpu_ack_i: Acknowledge/transfer-complete indication for the CPU-to-instruction-memory interface.
    - icpu_err_i: Error termination indication for the CPU-to-instruction-memory interface.
    - icpu_adr_i[31:0]: Instruction fetch address input associated with the returned instruction data (used for if_pc and buffering).
    - icpu_tag_i[3:0]: Tag field carried on the CPU-to-instruction-memory interface.
    - if_freeze: Freeze control for the fetch stage.
    - flushpipe: Pipeline flush request.
    - no_more_dslot: Indicates that no further delay-slot instruction should be executed.
    - rfe: Exception-return control indication.
Output port:
    - if_insn[31:0]: Instruction word presented to the decode stage.
    - if_pc[31:0]: Program-counter value accompanying the fetched instruction.
    - if_stall: Fetch-stage stall indication.
    - genpc_refetch: Request for the PC-generation logic to refetch the current address.
    - except_itlbmiss: Instruction-TLB-miss exception indication exported to exception control.
    - except_immufault: Instruction-MMU-fault exception indication exported to exception control.
    - except_ibuserr: Instruction-bus-error exception indication exported to exception control.
Internal reg/wire signals:
    reg [31:0] insn_saved: Instruction saved.
    reg [31:0] addr_saved: Address saved.
    reg saved: Saved.

Processing Flow

In each cycle, the module first determines the combinational IF-stage outputs from the current instruction-side interface signals and the internal saved state. For if_insn, error and control conditions have the highest priority. If icpu_err_i, no_more_dslot, or rfe is asserted, the module outputs the special NOP instruction. Otherwise, if a previously fetched instruction has been saved, the module outputs insn_saved. If no saved instruction exists but the instruction-side interface asserts icpu_ack_i, the module outputs the newly returned instruction icpu_dat_i. If none of these conditions is true, the module outputs the default NOP instruction.

At the same time, the module selects the PC associated with the IF-stage output. When a saved instruction is present, if_pc is driven by addr_saved; otherwise, it is driven by the current instruction-side address icpu_adr_i. The stall signal is asserted when there is no error, no acknowledge, and no saved instruction, indicating that the IF stage is still waiting for a usable fetch result. If a saved instruction already exists and another acknowledge arrives, genpc_refetch is asserted to notify the PC generation logic that the newly acknowledged fetch result may need to be fetched or handled again.

The module also decodes fetch errors in parallel. When icpu_err_i is asserted, the value of icpu_tag_i determines whether the error is reported as an instruction TLB miss, an instruction MMU fault, or an instruction bus error. These exception outputs are suppressed when no_more_dslot is asserted.

On each rising edge of clk, the internal saved state is updated. If rst is asserted, the saved flag is cleared, the saved instruction is set to the special NOP, and the saved address is cleared to zero. If flushpipe is asserted, the same saved state is cleared so that any buffered fetch result is discarded. Otherwise, when an acknowledge arrives while the IF stage is frozen and no instruction is already saved, the returned instruction and address are captured into insn_saved and addr_saved, and saved is set. When the IF stage is no longer frozen, saved is cleared, insn_saved is restored to the special NOP, and addr_saved tracks the current instruction-side address.

This flow ensures that returned fetch results are either passed directly to the pipeline, temporarily buffered during a freeze, or safely replaced by a NOP under idle, error, or control-transfer conditions.
