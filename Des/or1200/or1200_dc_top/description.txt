or1200_dc_top is the top-level wrapper of the OR1200 data-cache block. It connects the LSU/QMEM-side request interface, the external data bus interface, the data-cache FSM, the data RAM, the tag RAM, optional BIST wiring, and SPR-based cache-line invalidation.

The RTL instantiates three main submodules: or1200_dc_fsm, or1200_dc_ram, or1200_dc_tag.

The module drives dcsb_adr_o from dc_addr. dc_addr is generated by the data-cache FSM and is used as the common address source for the external bus address, the DCRAM index, and the normal Tag RAM index.

The cache invalidation path is controlled by SPR writes. The RTL defines dc_inv as spr_cs & spr_write. The Tag RAM write enable is dctag_we = dcfsm_tag_we | dc_inv. The Tag RAM address is selected from spr_dat_i[12:4] during invalidation, or from dc_addr[12:4] during normal cache operation. The Tag RAM valid bit input is dctag_v = ~dc_inv. Therefore, an SPR write into this block invalidates a selected cache line by writing the selected Tag RAM entry with valid=0. During normal FSM-controlled tag writes, the valid bit is 1.

The external write-data output dcsb_dat_o is always driven directly from dcqmem_dat_i, which is the LSU/QMEM write-data path.

When dc_en is low, the module bypasses the cache. In this mode, dcsb_cyc_o and dcsb_stb_o follow dcqmem_cycstb_i, dcsb_we_o follows dcqmem_we_i, dcsb_sel_o follows dcqmem_sel_i, dcqmem_ack_o follows dcsb_ack_i, and dcqmem_err_o follows dcsb_err_i. Read data returned to LSU/QMEM also comes directly from dcsb_dat_i.

When dc_en is high, the module uses FSM-generated control signals. dcsb_cyc_o and dcsb_stb_o are driven by dcfsm_biu_read | dcfsm_biu_write, dcsb_we_o is driven by dcfsm_biu_write, dcsb_cab_o is driven by dcfsm_burst, and the LSU/QMEM acknowledge and error responses are generated from the FSM first-hit, first-miss, and first-miss-error signals.

For cache-enabled, non-cache-inhibited BIU read accesses, dcsb_sel_o is forced to 4'b1111 so that a full 32-bit word is fetched. In all other cases, dcsb_sel_o follows dcqmem_sel_i.

Data written into DCRAM is selected by to_dcram. During BIU reads, to_dcram comes from dcsb_dat_i. Otherwise, it comes from dcqmem_dat_i. Whether DCRAM is actually written is controlled by the FSM through dcram_we.

Data returned to the LSU/QMEM side is selected by dcqmem_dat_o. When the cache is disabled, or when a first miss acknowledge occurs, dcqmem_dat_o comes from dcsb_dat_i. Otherwise, in cache-enabled operation, it comes from the DCRAM output from_dcram.

The tag-compare logic is combinational. It compares the stored tag read from or1200_dc_tag with saved_addr[31:13] and checks the valid bit tag_v. If the tag does not match, or if tag_v is clear, tagcomp_miss is asserted. This miss indication is passed to the data-cache FSM for hit/miss handling.

The LSU/QMEM response rules are selected according to dc_en. In cache-enabled mode, dcqmem_ack_o is generated from dcfsm_first_hit_ack or dcfsm_first_miss_ack, and dcqmem_err_o is generated from dcfsm_first_miss_err. In bypass mode, dcqmem_ack_o follows dcsb_ack_i and dcqmem_err_o follows dcsb_err_i. dcqmem_rty_o is simply driven as the inverse of dcqmem_ack_o. dcqmem_tag_o passes through dcqmem_tag_i unless an error occurs, in which case it returns the bus-error tag OR1200_DTAG_BE.

A compatible implementation should preserve the cache-enabled versus bypass split, the hit/miss data-return behavior, the refill and invalidation semantics, the external bus handshake behavior, and the interaction contract with or1200_dc_fsm, or1200_dc_ram, and or1200_dc_tag.

Processing Flow

1. The LSU/QMEM side issues a request through dcqmem_adr_i, dcqmem_cycstb_i, dcqmem_we_i, dcqmem_sel_i, dcqmem_ci_i, dcqmem_tag_i, and dcqmem_dat_i.

2. If dc_en is low, the module bypasses the cache. The request is forwarded directly to the external bus, and the external bus acknowledge, error, and read data are returned directly to the LSU/QMEM side.

3. If dc_en is high, the request is handled through the data-cache path. The FSM receives the request information, the tag-compare result, and external bus response signals, then generates cache control signals such as dc_addr, BIU read/write controls, DCRAM write enable, tag write enable, burst indication, and first-hit/first-miss response signals.

4. The tag RAM is accessed using the cache index, and the returned tag and valid bit are compared against saved_addr[31:13]. If the tag mismatches or the valid bit is clear, tagcomp_miss is asserted and passed to the FSM.

5. For cache hits, the returned data normally comes from DCRAM. For first-miss completion, or when the cache is disabled, the returned data comes directly from the external bus.

6. During BIU read/refill activity, external bus read data can be written into DCRAM under FSM control. During store-related DCRAM updates, LSU/QMEM write data can be written into DCRAM under FSM control.

7. If an SPR write occurs, the module performs software cache-line invalidation by writing the selected Tag RAM entry with its valid bit cleared.

8. The module returns acknowledge, error, retry, tag, and data signals to the LSU/QMEM side according to the selected cache-enabled or bypass path.
