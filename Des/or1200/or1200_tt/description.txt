The or1200_tt module implements the OR1200 Tick Timer logic. Its ports include the clock clk, asynchronous active-high reset rst, debug-unit stall signal du_stall, SPR access control signals spr_cs and spr_write, SPR address spr_addr, SPR write data spr_dat_i, SPR read data spr_dat_o, and the Tick Timer interrupt output intr. The main body of the module is controlled by the compile-time macro OR1200_TT_IMPLEMENTED.

When OR1200_TT_IMPLEMENTED is defined, the module implements the Tick Timer functionality. The actual storage implementation of TTMR and TTCR is controlled by OR1200_TT_TTMR and OR1200_TT_TTCR, respectively. If OR1200_TT_TTMR is defined, ttmr is declared as a 32-bit register and stores the Tick Timer Mode Register. If this macro is not defined, ttmr is declared as a 32-bit wire and is later tied to the constant value {2'b11, 30'b0}. If OR1200_TT_TTCR is defined, ttcr is declared as a 32-bit register and stores the Tick Timer Count Register. If this macro is not defined, ttcr is declared as a 32-bit wire and is later tied to 32'b0.

The module defines two SPR address select signals, ttmr_sel and ttcr_sel. ttmr_sel is asserted when spr_cs is 1 and spr_addr[OR1200_TTOFS_BITS]equalsOR1200_TT_OFS_TTMR; otherwise, it is 0. ttcr_selis asserted whenspr_csis 1 andspr_addr[OR1200_TTOFS_BITS] equals OR1200_TT_OFS_TTCR; otherwise, it is 0. These two signals are used in the SPR write path to indicate whether the current access targets TTMR or TTCR.

If OR1200_TT_TTMR is defined, ttmr is updated by an always @(posedge clk or posedge rst) sequential block. The block uses an asynchronous active-high reset: when rst is 1, ttmr is cleared to 32'b0. If reset is not active and ttmr_sel && spr_write is 1, the entire ttmr register is written with spr_dat_i on the rising edge of clk. If reset is not active, no software write to TTMR occurs, and ttmr[OR1200_TT_TTMR_IE]is 1, then only thettmr[OR1200_TT_TTMR_IP] bit is updated. Its new value is the OR of the previous IP value and (match & ttmr[OR1200_TT_TTMR_IE]). Because this branch itself requires IE == 1, in a cycle not overridden by reset or a software write, IE == 1andmatch == 1setIPto 1 on the rising edge ofclk; IE == 1andmatch == 0leaveIPunchanged. This hardware logic does not automatically clearIP; clearing or changing IPcan only be done by software writing the entireTTMR. If OR1200_TT_TTMRis not defined, there is noTTMRregister, andttmris combinationally tied to{2'b11, 30'b0}, meaning that its two most significant mode bits are 2'b11` and all remaining bits are 0.

If OR1200_TT_TTCR is defined, ttcr is updated by an always @(posedge clk or posedge rst) sequential block. This block also uses an asynchronous active-high reset: when rst is 1, ttcr is cleared to 32'b0. If reset is not active and restart is 1, ttcr is cleared to 32'b0. If reset is not active, restart is 0, and ttcr_sel && spr_write is 1, ttcr is written with spr_dat_i on the rising edge of clk. If none of the above conditions is true and stop is 0, ttcr is incremented by 1. If none of the above conditions is true and stop is 1, no assignment branch is taken in this sequential block, so ttcr retains its previous value. Therefore, the sequential update priority of TTCR is reset, restart clear, SPR software write, increment when !stop, and otherwise hold. If OR1200_TT_TTCR is not defined, there is no TTCR register, and ttcr is combinationally tied to 32'b0.

The SPR read data is generated by a combinational always @(spr_addr or ttmr or ttcr) block. This combinational logic produces spr_dat_o only from spr_addr[OR1200_TTOFS_BITS], ttmr, and ttcr; it does not use spr_csas an output gating condition. WhenOR1200_TT_READREGSis defined, if the address offset equalsOR1200_TT_OFS_TTMR, spr_dat_ois assignedttmr. All other address offsets enter the defaultbranch, wherespr_dat_ois assignedttcr. Therefore, in this implementation, all offsets other than the TTMRoffset read outttcr; it is not the case that only the TTCRoffset reads outttcr`, and unknown offsets do not read as zero.

match is a combinational comparison signal. The code compares ttmr[OR1200_TT_TTMR_TP]withttcr[27:0]; if they are equal, matchis 1, otherwise it is 0. The comparison uses the threshold field ofTTMRand the lower 28 bits ofTTCR. TTCR[31:28]` does not participate in the match comparison.

restart is a combinational control signal. It is 1 when match is 1 and ttmr[OR1200_TT_TTMR_M]equals2'b01; otherwise, it is 0. This signal feeds the sequential update logic of TTCR, where it has higher priority than software writes to TTCRand natural incrementing. Therefore, whenTTCRis implemented as a register, as long as reset is not active,restart == 1clearsttcrto zero on the rising edge ofclk`.

stop is a combinational control signal. It is the OR of three conditions: match is 1 and ttmr[OR1200_TT_TTMR_M]equals2'b10; ttmr[OR1200_TT_TTMR_M] equals 2'b00; or du_stall is 1. stop is used only to control the natural increment path of TTCR. When stop == 1, if there is no reset, no restart, and no software write to TTCR, ttcr holds its previous value. When stop == 0, if there is no reset, no restart, and no software write to TTCR, ttcr increments on the rising edge of clk. du_stall prevents the natural increment through stop, but it does not block reset, restart clearing, or software writes to TTCR.

Based on the definitions of restart and stop, the effect of the TTMR[M] field on the counter can be described precisely in four cases. When M == 2'b00, stop is 1 and restart is 0, so in the absence of reset and software writes, TTCR holds its value. When M == 2'b01, if match is 1, restart is 1 and TTCR is cleared; if match is 0 and du_stall is 0, TTCR increments; if match is 0 and du_stall is 1, TTCR holds its value. When M == 2'b10, if match is 1, stop is 1 and TTCR holds its value; if match is 0 and du_stall is 0, TTCR increments; if match is 0 and du_stall is 1, TTCR holds its value. When M == 2'b11, match does not assert restart and does not assert stop; therefore, when du_stall == 0 and there is no reset or software write, TTCR continues to increment.

The interrupt output intr is a continuous combinational assignment directly equal to ttmr[OR1200_TT_TTMR_IP]. Therefore, intrreflects theIPbit currently stored inTTMR. matchdoes not directly driveintrthrough combinational logic.matchcan only setIPthrough theTTMRsequential logic on the rising edge ofclk, and only when TTMR[IE] == 1, reset is not active, and no software write to TTMRoccurs in the same cycle. AfterIPis updated,intrfollows the updatedIP` value.

When OR1200_TT_IMPLEMENTED is not defined, the module does not implement the Tick Timer main logic. In this branch, intr is continuously assigned 1'b0. If OR1200_TT_READREGS is also defined, spr_dat_o is continuously assigned 32'b0. If OR1200_TT_READREGS is not defined, this branch contains no assignment to spr_dat_o.

Overall, the module has no additional state machine. Its behavior is composed of the optional TTMR and TTCR registers, SPR address decoding, the match comparison logic, the restart and stop control logic, and the direct connection from IP to intr. The sequential update priority of TTMR is reset, software write, and hardware update of IP. The sequential update priority of TTCR is reset, restart clear, software write, increment when not stopped, and otherwise hold.

Processing Flow

On each cycle, the module first determines whether the current SPR access targets TTMR or TTCR by decoding spr_cs and spr_addr. The decoded select signals ttmr_sel and ttcr_sel are used only for write-side register updates.

The module continuously compares the threshold field TTMR[TP] with TTCR[27:0] to generate the combinational match signal. Based on match and the mode field TTMR[M], it also generates the combinational restart and stop control signals. restart is asserted only when match == 1 and TTMR[M] == 2'b01. stop is asserted when match == 1 and TTMR[M] == 2'b10, when TTMR[M] == 2'b00, or when du_stall == 1.

On the rising edge of clk, or immediately on the rising edge of rst, the implemented registers update according to their priority rules. If TTMR is implemented, reset clears it to zero. Otherwise, a software write to TTMR loads the entire register from spr_dat_i. If no reset or software write occurs and TTMR[IE] == 1, the hardware updates only TTMR[IP]; under this condition, match == 1 sets IP to 1, while match == 0 leaves IP unchanged.

If TTCR is implemented, reset clears it to zero. Otherwise, restart clears it to zero. If no reset or restart occurs, a software write to TTCR loads it from spr_dat_i. If none of those conditions occurs and stop == 0, TTCR increments by 1. If stop == 1 under those same conditions, TTCR holds its previous value.

The interrupt output intr is continuously driven by TTMR[IP]. Therefore, a match event does not directly assert intr; it first sets IP through the TTMR sequential update logic, and intr then reflects the updated IP value.

The SPR read data path is independent of the write-side select signals. When read-register support is enabled, the read mux returns TTMR for the TTMR offset and returns TTCR for all other offsets. This read mux is not gated by spr_cs.
