The alu module is the core combinational arithmetic logic unit in the execution stage, or EX_stage, of the mips_16 processor. According to the specification document, MIPS_16 uses a 16-bit data width and adopts a classic 5-stage static pipeline structure. In this pipeline, the main function of the EX_stage is to perform ALU operations. In this module, the ALU receives two 16-bit source operands, a and b, and selects the corresponding arithmetic, logic, or shift operation according to the 3-bit control signal cmd. The 16-bit operation result is then output through r and passed to the following MEM_stage or WB_stage.

The input ports of this module include a, b, and cmd. The signal a is the first 16-bit source operand, usually from the source register data read from the register file. The signal b is the second 16-bit source operand, which may come from another register, an immediate extension result, or be used as the shift amount in shift operations. The signal cmd is a 3-bit ALU control signal that indicates which operation should be executed. The output port r is a 16-bit register-type output used to store the ALU result generated by the current combinational logic. Since this module has no clock or reset signal, r is not a sequential register. Instead, it is a combinational logic output that is updated in real time inside the always @(*) block according to changes in the inputs.

module alu
(
	input		[15:0]	a,		//src1
	input		[15:0]	b,		//src2
	input		[2:0]	cmd,	//function sel
	
	output	reg	[15:0]	r		//result	
);

Processing Flow

the alu module first responds to changes in all input signals through the always @(*) block. Whenever a, b, or cmd changes, the module re-enters the case(cmd) decision process. The specific values of cmd are defined by ALU control macros in mips_16_defs.v, such as ALU_ADD, ALU_SUB, ALU_AND, ALU_OR, ALU_XOR, ALU_SL, ALU_SR, and ALU_SRU. The control logic table in the specification also shows that instructions such as ADD, SUB, AND, OR, SL, SR, SRU, ADDI, LD, and ST drive the EX_stage through the ALU control field to perform the corresponding operation.

When cmd is ALU_ADD, the module executes a + b, implementing a 16-bit addition operation. This operation can be used not only for the ADD instruction, but also for the ADDI immediate addition instruction and address calculation in LD and ST instructions. When cmd is ALU_SUB, the module executes a - b, which is used for subtraction instructions or comparison-related calculations. For logic operations, when cmd is ALU_AND, ALU_OR, or ALU_XOR, the module performs bitwise AND, bitwise OR, and bitwise XOR operations respectively. These operations are applied directly to each bit of a and b, producing the corresponding 16-bit logic result.

Shift operations are implemented by the three control commands ALU_SL, ALU_SR, and ALU_SRU. When cmd is ALU_SL, the module executes a << b, which shifts operand a left logically by the number of bits specified by b. For arithmetic right shift, ALU_SR, the code uses {{16{a[15]}}, a} >> b. This first extends the sign bit a[15] of a into the upper 16 bits, then concatenates it with the original a to form a 32-bit value before shifting right. In this way, the sign bit is preserved during the right shift, implementing a signed arithmetic right shift. For unsigned logical right shift, ALU_SRU, the code uses {16'b0, a} >> b, which pads the upper 16 bits with zeros before shifting right. Therefore, zeros are always shifted into the left side, and the sign bit is not preserved.

When cmd is ALU_NC, the module assigns 16'bx to the output r, indicating that the current ALU result is don’t-care or invalid. This case is usually used in control paths where the ALU does not need to generate a valid result. When cmd does not match any defined ALU control command, the module enters the default branch and sets the output result to 0. At the same time, in a non-synthesis environment, if CODE_FOR_SYNTHESIS is not defined, the module prints an error message through $display to report the unknown ALU command. This mechanism is mainly used for locating and debugging problems during simulation.
